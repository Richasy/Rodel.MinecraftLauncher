# 启动器 AI 实现规格

故障修复已接入实例/故障绑定的Core委托、CLI/MCP专用工具和App入口，复用既有ask_user。具体动作、回退与真实验证范围集中在[AI故障修复](../design/AI-REPAIR.md)，不由模型回复或HTML示例推定游戏已恢复。

架构：CLI / Sprout → Core → 内部AI子模块；App不携带CLI，独立CLI保留对外MCP。非UI的授权/恢复/托管工具/第三方与外部安装纵切已实现，不代替原生界面验收。来源抽取checkpoint仍是可演进实验，不是无损或实战最佳实践声明。

本规格定义**启动器 AI**：玩家配置自己的模型服务，在启动器中多轮对话，使用技能与工具完成真实操作，并将启动器能力安装到外部 AI 客户端。Core/CLI已有服务/模型/凭据、五协议、持久多轮/流式/取消/历史、权限/精确确认/intent与未知效果、真实job观察、授权文件快照/提交、公开API检索/网页、第三方MCP回合和Codex/Claude安装；具体做法/固定来源见[托管工具说明](AI-MANAGED-TOOLS.md)。自动压缩继续保留独立的实验定位。HTML为模拟参照；Core、CLI、原生App及游戏桥分别验证。文中的“必须”是验收要求，“可”是允许的实现选择。

完整交付必须包含 Core 应用入口、CLI 可操作路径、真实模型与文件/任务证据、正常 packaged NativeAOT 原生验证。仅 HTTP 连通、模拟 UI 或模型自述成功均不算完成。各平台未取得实际测试条件时逐项记录未验收，不以另一平台通过替代。

## 3. 玩家流程

1. 玩家首次打开 AI 页，未配置服务时显示添加服务入口；不影响普通启动器使用。
2. 在全局“设置 → AI 助手”通过两步添加：先选服务并填写所需地址/密钥，本地Embedded不填写服务地址或密钥，再获取模型列表、勾选需要的模型后添加。显示名称放在表单顶部，不再提供凭据方式、服务状态和设计验证字段；列表失败或为空时仍可手填并保存离线配置。
3. 新建会话，选择服务/模型及可选实例上下文，输入问题。发送前明确本轮接收数据的服务和启用工具范围。
4. 逐步呈现回答；工具执行以可展开的记录显示名称、目标、阶段和真实结果，后台作业显示实际进度。
5. 模型需要修改设置或安装内容时，按第 7 节执行，成功后回读状态。正在执行的回合不会因玩家切页或切实例而更换目标。
6. 玩家可停止本轮、离开页面、切换历史或继续提问；重启后能查看已保存的记录和未完成原因。
7. 文件/网络 MCP 随应用提供，自动就绪，无需玩家安装运行环境、配置命令或检索密钥。文件与网络的默认开关为独立设置，初始均为开启，应用于新对话，不写入模型绑定；每段对话可用输入区开关调整，切换模型不改变默认值或当前对话的开关。在输入区分别用高亮图标表示，可随时关闭。需要分析本地日志/配置时在全局设置添加目录与读写范围；查模组或服务更新时检索来源并读取具体页面。普通已授权访问不逐次打断询问。
8. 外部工具设置中选择 Codex/Claude Code，预览写入位置，安装技能和 MCP；可分别更新、检查和移除。

## 4. 服务、凭据与模型

### 4.1 服务配置

服务类型列表只保留四项，选项标题下用小号灰色文字说明：

| 类型 | 说明 |
| --- | --- |
| OpenAI 服务及兼容 API | 兼容 OpenAI 接口的服务，如 DeepSeek, Azure OpenAI等 |
| Anthropic 服务及兼容 API | 支持 Anthropic 服务及兼容其 API 的服务。 |
| Gemini 服务及兼容 API | 支持 Gemini 服务及兼容其 API 的服务。 |
| 本地模型 | 支持基于 llama.cpp 的本地模型推理。 |

服务家族与实际调用协议分开：选择 OpenAI 后在第一步明确显示 API 类型选择（Responses API / Chat Completions API，默认 Responses）；其他家族不显示这个控件。两种 OpenAI 协议都适用于原服务或兼容端点，不另造“兼容服务”家族；切换 API 类型保留地址与凭据，保存/编辑/返回步骤保留实际协议，不能根据品牌猜测协议或失败后自动切换。本地模型是玩家可见名称，内部使用Rodel.Inference Embedded，不重新实现推理后端，也不要求玩家运行独立服务。下拉说明只在展开选项时显示，收起显示标题；说明通过无障碍描述关联选项。

新增采用两步流程：“连接服务 → 选择模型”。第一步选择服务家族，显示可编辑服务地址和必要凭据；OpenAI 家族再明确选择 API 类型。端点可预填默认值，允许接入兼容服务和本地地址。显示名称位于表单顶部，留空时使用服务名称；后续只展示服务类型、适用的API类型、密钥及地址。删除本表单的高级设置、凭据方式、服务状态与设计验证控件，新服务默认启用，本地模型无需密钥，不要求玩家判断工具能力。第二步自动读取列表，支持多选；手填模型通过平面“手动添加模型”入口就地显示独立输入区域，区域使用轻底色和细边框，包含显示名称与模型标识两个输入（名称留空使用标识），不使用折叠标题或原生三角标记；空列表/鉴权失败/离线时直接显示输入行，并保留返回修改连接的路径。获取列表成功不代表模型回答或工具能力已验证。移除图标固定在输入区域最右侧，与输入框底部对齐，窄窗也不能掉到左下角。模型列表只在条目之间分隔，最后一项无下划线，添加入口与上一条模型留10px间距，按钮左右各保留12px内边距。移除时同时清空未提交名称和标识并返回添加入口；返回上一步保留输入与模型勾选。两步间保留输入与选择，最终添加前不登记服务/模型，取消不留下半成品；临时凭据随取消清理，不写入诊断。首次添加自动选一个模型供新会话使用，后续添加不改当前模型。已有服务的连接编辑不修改模型清单；单独添加/编辑模型只要求标识，显示名可选，不提供能力配置。

`AiServiceProfile` 至少包含稳定 ID、显示名、协议类型、基址、凭据引用、启用状态和配置修订号。协议枚举为 `openai-responses`、`openai-chat`、`anthropic-messages`、`gemini`、`rodel-inference`。OpenAI 官方服务默认 Responses；兼容服务允许明确选择 Chat Completions。不得失败后静默改协议、换模型或切云服务。

保存验证地址格式和必需字段，不要求网络在线。远端基址以明确的 API 根地址配置，组装路由时不重复追加路径，不将 query 中的参数误当路径；拒绝 URI 内嵌账号口令。默认 HTTPS；独立兼容服务允许loopback HTTP，玩家显式配置的其他HTTP地址需在保存处说明传输性质，不静默升级或替换端点。Embedded本地配置的基址与凭据引用均为null；旧记录若仍带外部端点/凭据则明确拒绝并要求重新保存或选择兼容API，不静默忽略原目标。认证信息不跨主机重定向转发。

云端凭据使用 Windows 当前用户保护的秘密存储，普通配置仅保存不透明引用；具体实现采用 DPAPI CurrentUser 加受限文件权限，不以混淆或 Base64 代替保护。可选读取玩家指定的环境变量，但不把变量值回写。主数据目录搬到另一机器而凭据无法解密时，服务配置和历史仍可读，提示重新填写凭据。

服务编辑不改写已完成轮次的服务快照。在途回合固定配置修订；修改或移除服务仅影响后续发送。移除凭据等待在途引用释放后清理，历史保留服务显示名与模型，不保留密钥。日志、诊断导出、工具结果、剪贴板配置和外部安装内容不得包含凭据明文。

### 4.2 模型与能力

`AiModelBinding` 包含 serviceId、模型/部署/profile 标识、显示名及用户覆盖的请求参数。模型列表失败或不提供列表时保留手工配置；列表空不等于服务不可用。默认模型只影响新会话；会话切换模型只影响下一轮，并记录该轮实际选择。

模型列表不提供能力标签、能力选择表单或预设白名单，不以“仅文本”“工具能力待核验”等人工分类限制模型选择或事先阻止调用。文件/网络工具是否提供，由独立访问设置与实际授权决定，不由模型配置决定；协议请求仍须真实处理上游返回的不支持字段/调用错误，不丢弃工具后冒称已经执行，不伪造模型能力或结果。

温度、最大输出等参数只在服务适用时发送；未设置时使用服务默认。单次`AiTextRequest`允许有限温度与正数输出上限的临时覆盖，CLI的`ai request`映射相同typed字段，不为此改写保存的模型默认值；结果返回实际请求参数。上下文长度估算不是加载参数，不能替玩家修改 Inference profile。usage 无返回就显示未知，不估算为零或编造费用。模型服务的连接测试、列模型、普通回答和工具调用分别记录状态。

Rodel.Inference必须显式使用Embedded：调度与控制面在调用者进程，原生推理由库拥有的worker完成，不发现默认端口、不连接独立rin daemon。Core缓存引擎，请求借用与取消不自动卸载；显式卸载等待当前借用释放，只清理本runtime拥有的资源，后续允许重新加载，不影响其他进程的引擎。模型配置接受SDK模型库引用或已有GGUF绝对路径，沿用同一字段与会话流程；文件入口不复制/登记权重；CLI目录列举只读取SDK模型库，App本地添加直接登记所选GGUF，不进入SDK目录发现。GGUF解析、分片/配套文件、加载/推理与模型/运行时管理归Inference，不在启动器另建导入体系。文件入口及显式加载设置已在Inference main，依赖固定为c3a4725。可选的本地contextLength按模型保存并透传SDK ModelLoadOptions；未配置的新/旧绑定统一在Core请求捕获时采用启动器64K默认，若GGUF标注更小则取标注；显式值仍优先，ClearContextLength只清除上下文覆盖并保留温度/输出设置。App用每模型独立Slider与恢复默认承接该契约。默认不改写旧配置或SDK全局策略，实际值在请求/回合元数据可见；不与历史字符/输出预算混用，也不作为模型品牌或工具能力门槛。Azure与独立兼容服务使用通用OpenAI基址/凭据/模型配置，不设品牌专用分支。

### 4.3 协议归一化

每个适配器必须转换文本增量、消息结束、工具调用参数、调用结果、取消、usage 和实际错误。提供商返回的必要 opaque continuation/signature 作为仅宿主可见的协议状态保存并按原要求回传，不改成普通文本、不混进另一个模型的历史；切模型时只投影可移植文本、图像与已完成工具结果，并记录上下文切换。

工具图像使用标准MEAI DataContent保存和续传，MCP客户端消费实际解码字节，不读取返回路径来补图。工具结果与图片关联必须经过完整批次，不能在其他待回传的tool结果前插入OpenAI user图片观察，也不能向本地SDK传入会被拆成无call ID的tool图片。压缩可替换工具文本但不删除当前图片，旧图可经同会话精确归档读取恢复。公开状态、效果报告和可见事件不携带图体，原始intent与私有历史保留；恢复图片不构成重新执行工具。

工具参数增量必须组装完整、解析和校验后执行；中断的半段 JSON 不执行。保留提供商实际 call ID；工具名由宿主映射到稳定 ID，不让模型自造名称或覆盖工具身份。只有提供商实际返回的可展示推理摘要可折叠显示，不要求模型暴露内部思考，也不把其计入已验证事实。明确推理 item/block 或正数 reasoningTokens 可作为独立的无摘要状态证据，不能解密或把计数转成思考文本；若只在完成 usage 时得知，不伪造更早的思考开始时间。

## 5. 会话、回合与持久化

### 5.1 数据实体

| 实体 | 必需信息 |
| --- | --- |
| `AiConversation` | ID、标题、创建/更新时间、下一轮默认模型与上下文、修订号 |
| `AiMessage` | ID、角色、内容块、时间、完成/部分状态、所属 turnId |
| `AiTurn` | ID、客户端幂等键、模型/服务修订、实例快照、工具/技能/文件与网络授权快照、预算、归属模式、状态、结果引用 |
| `AiToolInvocation` | 调用 ID、工具来源/版本、原始有效参数、目标、执行状态、实际结果/作业引用 |
| `AiEvent` | 协议版本、conversationId、turnId、递增 sequence、UTC 时间、事件类型与数据 |

实例快照至少有真实 ID、名称、数据根身份和本轮实际读取的版本/配置摘要。快照用于表达发送时上下文；执行修改时仍调用 Core 检查最新状态，不用旧快照覆盖玩家的新设置。未选实例允许全局和普通对话；需要实例的动作必须选择明确目标，不能猜“第一个实例”。

记录按 `DATA_ROOT/ai` 保存：服务元数据、会话索引、逐会话消息/回合及事件、技能/MCP 配置、外部安装清单分别存储；旧 `ai/tasks` 保持原格式可读。秘密材料与普通记录分离。格式包含版本，保留未知可选字段，遇到未知必需版本只禁用该记录的修改并允许查看可读部分。

会话元数据采用临时写入与可恢复替换；事件先持久化再发布，文本增量允许有界合批。崩溃只恢复已落盘的部分内容，JSONL 尾部不完整行可隔离，不能丢弃整个历史。索引可从有效记录重建；单份损坏不遮住其他会话。存储写失败时停止后续工具调度，保留已发生效果并给出明确错误，不能继续无记录地修改实例。

有副作用的调用在执行前写入并刷出 intent：invocationId、目标、有效参数、原状态/审核指纹、能力授权修订和可用的恢复查询键；持久化失败不得开始执行。执行后记录结果/作业引用。若结果落盘前崩溃，恢复器按 intent 与 Core journal/jobId/文件哈希查询，确定成功/失败或保留 `unknown_effect`；没有足够证据时由明确核查操作接续，不能交给模型猜完成，更不能自动重放写动作。intent/result 仅保证可追踪，不伪称外部效果恰好执行一次。

### 5.2 状态与并发

一个回合：`queued → connecting → generating ↔ executing_tool → completed`；压缩时为`compacting`，完成后回到生成。需要执行确认时进入 `awaiting_confirmation`，接受后执行，拒绝后以拒绝结果继续模型回合。非终态可转 `canceling → canceled`、`failed`、`incomplete` 或 `interrupted`。终态不可被迟到的文本/工具回调覆写。`completed` 只表示本段正常结束（包括明确的排队消息交接），目标效果由工具结果另行判断。

每个数据根同时执行一个AI回合；同一Core宿主接收的新消息持久化为queued，默认按接收顺序自动推进。同会话有补充消息时，当前模型请求及其整批工具调用先完成，在下一次模型请求边界交接最早的有效排队项；不必等待原任务给出最终回答，也不取消正在执行或等待明确回答/许可的工具。原回合以completed和finishReason=queued_message结束本段，turn_yielded事件关联下一项；这只表示本段交接，不宣称玩家目标或后台任务已经完成。排队时冻结提示、图片、模型/实例及权限快照，开始执行时按实际执行顺序接续已结束回合的完整历史，包括已提交的工具返回；尚未执行及未派发取消项不进入上下文。其它会话不能触发本段交接或进入当前上下文，其待执行项相对顺序保留。排队项可单独取消；立即发送将指定项移到下一轮，并主动停止同会话的活动回合，其余队列保持相对顺序，不打断其他会话。优先动作不重新提交消息，重复点击已开始的项不再次取消或发送。删除会话或停止宿主会取消其待执行项。宿主中断后保留中断记录，不自动重放队列或未知效果。重复客户端幂等键返回原turnId，不新增排队项。配置与会话写入继续检测修订冲突；其它进程拥有生成租约或非聊天生成占用时仍返回AI_BUSY，不建立另一条竞争队列。

支持新建、列表分页、打开、重命名、删除、复制消息和导出可读文本/结构化记录。App新会话自动生成标题：本地模型从首条用户消息提取最多24个文本元素；云端模型并行发起独立标题请求，只发送首条文本的有界片段，不带工具、图片、完整历史或正文输出。云端标题有独立15秒超时及最多512输出token预算（包括推理），不占用聊天生成队列；实际usage保留在会话titleGeneration中。正文先结束，标题稍后更新，不保持loading或阻塞下一轮；失败使用首句标签。用户手动重命名优先。CLI显式选择GenerateTitle使用同一规则，未启用时保留其命名行为。活动会话删除先停止并等待其回合终态；删除历史不取消已独立运行的安装作业或游戏，先显示这些仍活动的引用。首版不做消息编辑、分支树或一键重新执行整段历史。

### 5.3 停止、退出与恢复

停止首先撤销后续工具调度，再取消模型请求和当前可取消的前台工具。已经进入 Core 提交阶段的工作按其原子提交/恢复语义完成；界面不能提前宣称没有副作用。模型停止不等于游戏退出，也不等于后台作业取消；作业卡提供独立取消入口。

切页、切历史和最小化不停止生成。回合归属明确为 `client_owned` 或 `host_owned`：App 默认前者，退出时取消自己拥有的回合并有界收尾；CLI send 默认后者，宿主持久接管，命令退出不取消，`--wait` 仅观察，显式 `--cancel-on-exit` 才采用客户端归属。宿主有 host_owned 活动回合时不能因无客户端退出，结束后按空闲规则收尾；客户端启动时间用于判定真实归属，观察者断开不接管。不要结束用户共享的 Inference 或外部 AI 客户端。宿主异常退出后将该次活动回合标记 `interrupted`，重启显示已有部分内容、实际工具结果和待核查项，不自动重放。已经执行但未拿到结果的变更记录 `unknown_effect`，先查询真实状态，不能自动再次执行。

正常对话由玩家直接在输入框继续发言，不显示“接续提问”或为下一轮预填旧问题的按钮。同一个目标中的模型/工具循环、已提交任务的观察与结果整理由助手自动推进，不要求玩家反复说“继续”或手动再发送原目标；只有实际缺少选择、能力范围或产品固有确认时才等待相应交互，交互完成后自动继续原目标。

失败“重试”是新回合：点击后直接沿原问题发起新 attempt，不先填入输入框再让玩家点发送；已执行工具的回合保留其结果，明确接续剩余工作，不盲目重新运行。自动网络重试只适用于尚未发布增量、尚无工具效果的请求，首版最多 2 次，遵循 Retry-After；鉴权错误不自动重试。需要核对未知效果的回合先核对，再决定后续步骤，不提供盲目重放。

## 6. 上下文与预算

英文专项设计与参考来源见[Context Compression: Exploratory Design](AI-CONTEXT-COMPRESSION.md)。以下实现属于初具雏形的原型，不是经过实战验证的实践；切分、保留、选择、预算及表示方式均可随证据继续更改，不把当前数值和算法冻结成产品保证。

system 内容分层：产品核心规则、当前工具/技能目录、玩家自定义助手偏好、会话历史、本轮输入与最小实例摘要。自定义偏好是文本配置，不是任意代码；技能和外部数据不能覆盖产品执行边界。

发送前仅注入所需的实例摘要，不自动读取全部日志、存档或本地文件。模型需要更多信息时通过明确工具查询。对话显示当前服务与数据上下文；日志等结果按现有脱敏规则处理，脱敏不承诺覆盖玩家手工输入的所有私人信息。其他实例只有明确选为目标或用户授权跨实例任务时才可修改。

皮肤聊天允许每轮显式附加最多3张PNG/JPEG/WebP参考图，由Core冻结原始字节并校验摘要。图片属于消息内容，不是目录授权或皮肤导入；相同clientKey重复提交和失败继续保持原图，历史重开与provider切换保留标准MEAI多模态内容。服务端计数可用时包含真实图片输入，否则本地仅计文本、标记图像token未计入，不将base64 BPE或未知视觉能力当作压缩/发送门槛。

每回合默认最多64次模型调用；不再人为设置4096等默认输出上限，也不拦截大于65536的显式正数。输出参数优先级为本次显式设置、模型保存值、provider真实输出容量、精确provider/model匹配的models.dev容量；没有可靠容量时省略参数，由服务决定。聊天与单次请求复用同一能力解析，不猜测其他部署的同名模型容量。历史不再设64000字符准入上限；`HistoryCharacters`、CLI `--history-characters`及界面字符预算调节已删除。服务端决定可接收的上下文，客户端不以字符数冒充token容量。

压缩时归档完整旧交互，保持工具调用与结果配对，保留最初目标、最近对话、事实来源及归档引用。提供 `result_read` 或同等归档读取工具；压缩不删除聊天展示原文，不重放工具。上下文拒绝最多额外压缩重试 1 次；仍失败则以可恢复错误结束。达到轮数/输出预算时标记 `incomplete`，展示实际原因和继续入口，不能写成任务完成。

**多语种验收约束**：面向多语言玩家，中文是算法设计与语义验收的首要语言，不作为英文方案通过后的附加翻译测试。至少独立覆盖中文、英文、中英混排以及带原文技术标识的多语种记录；其他语言持续补充证据，不据未验语言禁用普通对话，也不宣称中文通过等于所有语言通过。不能以multilingual模型标签、Unicode可读或英文benchmark代替中文效果。

中文重点覆盖否定/双重否定、条件与先后关系、指代/省略、用户纠正、已完成/尚未/未知效果、中文同名实体和精确版本/单位；中英混排中的工具名、JSON键、命令参数、路径/hash/ID不翻译或改写。分段不得依赖英文空格或英文停用词表；不能机械删“不、未、仅、除非、先、再”等词。默认不先将中文翻译成英文再压缩，源片段/来源语言保留，摘要表达与原文标识分别处理。

质量按语言分别统计约束/事实保持、假完成/臆造、续办行为和连续多次压缩退化，不用总体平均掩盖中文失败。压缩收益优先使用所选模型tokenizer或真实provider usage，同一任务计入摘要/检索的总成本；字符数、UTF-16长度和JSON中的`\uXXXX`长度不得冒充跨语言token数。压缩搜索中的wire字符尺度只是工程计量，不是发送门限，也不证明中文与英文等效；新策略须显式处理这种语言偏差。质量未达到时降低有损程度、保留关键原文或按需读取，而不是把模型本来能处理的语言列为不支持。

**当前token计量**：服务端支持时优先调用Responses `responses/input_tokens`、Claude `messages/count_tokens`或Gemini `countTokens`，内容来自实际请求的system、工具schema、历史与合法原生续传。否则使用`Microsoft.ML.Tokenizers`的Tiktoken/o200k_base对输入表示做真实BPE计数，并按同一服务修订/模型返回的input usage进行EWMA拟合；它仍明确标记为估算，不能声称是DeepSeek/Claude的精确tokenizer。Claude缓存读写输入计入实际输入量。计量/拟合不可用不阻断生成，拟合只保存数值，不保存prompt或凭据。

容量优先采用当前provider实际返回的context_length/context_window或inputTokenLimit/max_input_tokens；输入独立上限不重复扣除输出，总上下文容量才预留输出。models.dev本地快照提供公开参考，只有实际服务host匹配时可用于建议预压缩，未知代理同名模型只报告目录参考值，不据此判断部署容量。约90%触发预压缩建议；选择器失败、无剩余额度或本地估算失败均降级为原窗口发送，且保留至少一次正常生成调用。真正provider上下文拒绝且未发布回答/思考增量时，最多安全压缩并恢复一次，不将普通400或工具大小错误误判为上下文错误。

[models.dev](https://models.dev/)提供随包MIT署名快照和data-root下最后有效快照：本地立即查询，到期（24小时）在后续使用时后台单任务刷新，失败退避一小时并保留旧数据；不需要独立常驻任务。目录请求固定匿名HTTPS，不携带模型凭据或聊天内容，限制下载大小/时间并原子替换。provider logo按实际host匹配，模型作者按canonical_model_id匹配lab；logo按需缓存七天，失败保留旧logo或使用内置图标。公开数据不证明特定代理部署的容量。

压缩搜索内部仍用实际请求Unicode字符衡量候选是否变小，这只是有界搜索尺度，不是发送容量、token计量或用户可调预算；原文引用与token收益分别记录。

先在会话目录`context-archives`原子保存完整私有历史及SHA256。保留首个用户目标、最新输入、当前输入之后为协议续传所需的完整assistant/tool组与product system；旧内容形成有archiveId/messageIndex/offset/length的原文条目。短用户消息（当前≤2048 UTF-16单位）整条保留，避免把中文纠正、条件和指代拆成失联句；长消息首尾条目保留，中间文本按完整句/段抽取。JSON样式内容和fenced代码不按内部句号/字段拆开，不机械删词或翻译标识。已完成的成功工具观察可按相关性选择，不永久必留；未知/失败效果继续保留真实状态及来源，不能据checkpoint重放操作。结构化旧工具结果由Core形成真实状态/错误/来源引用，不让模型改写执行结果；大结果必要时外置，原文可读，不补造成功或重放工具。

失败回合中的工具返回即使为清理协议状态而以user角色传递，仍按host保留的调用ID/工具名识别为观察数据，不能升级为用户指令。旧checkpoint引用此类记录时回到原归档验证并重建状态/引用；短观察也不能因user角色重新展开成必留全文。执行状态和原始payload继续由可读归档承接，不重放历史调用来取回结果。

**模型只做选择，不生成checkpoint事实**：相同服务/模型在无工具请求中对可选原文返回`keep/omit`整数ID，ID仅在当前有界包内有效；Core校验每个ID恰出现一次、无编造/漏报/重复，按来源原顺序组装原文。每条给出Core计算的保留成本，选择结果超预算即拒绝，不能悄悄裁短。已保留的来源条目按稳定引用增量带入，逐条与原始归档验证；旧自由文本checkpoint读取其原始归档重建，不继续传播其中的虚构任务状态。来源/保留/省略数量由Core计算，不让模型声称“已读完某些行”。这保证引用文字真实，不保证任何被省略信息对所有未来任务都无用。

窗口确实缩小时才原子安装。失败保留原文：提前压缩的可恢复错误记录内部deferred事件并继续原请求，不反复在正文发警告；真实服务端拒绝且无安全缩小路径时保留实际错误。选择调用共享本轮64次模型调用及时间/输出/取消预算，不额外硬套2048 tokens输出限制；本地选择输入按token估算分包并预留推理/输出空间，每个来源ID恰好分类一次，原文不截断或静默丢弃。结果不作为聊天回答增量。`context_compaction_started/progress/finished`、`context_compacted`记录实际阶段、单位覆盖与usage；上下文拒绝在无已发布增量时最多压缩恢复一次，第二次拒绝停止。

原文通过`AssistantService.ReadContextArchiveAsync(AiContextRead)`、`ai chat archive`或仅当前会话的`conversation_history_read`工具分页读取，字符页256～16000，支持messageIndex/offset并保护Unicode边界。`--no-tools`不开放该模型工具，但显式Core/CLI读取仍可用。来源与取舍见[压缩设计](AI-CONTEXT-COMPRESSION.md)。本地调度/归档不等于模型计算在本机：云模型仍接收供选择的旧原文；不同服务及模型的效果分别验证。

完整选中条目在私有回合`contextCheckpoint`保存，`summarySource=host_validated_extractive`；`summary`是Core组装的带来源文本，不是模型总结。公开`GetTurn`不返回整份excerpts，给出excerptCount及最多8000 UTF-16单位的summary预览、summaryCharacters/summaryTruncated；完整源内容通过归档分页，不让高预算窗口撑破后台协议帧。界面/导出不得把被标注截断的预览当完整上下文。保留窗口中的合法原生续传仍只发给原协议/模型/修订，选择请求/公开归档页均不包含opaque签名或推理原文。

## 7. 工具执行与设置修改

### 7.1 同源调用

内置助手复用现有目录、Core 服务、typed 任务与错误码。工具新增集中维护一份定义，CLI/MCP/内置 AI 同步可见。补齐启动器全局/实例设置读取、字段元数据、批量编辑/移除覆盖、Java/内存/参数配置等所需工具；优先复用主线最新 typed 能力，不能只给模型一个拼 CLI 字符串的入口来冒充结构化支持。

设置修改以 patch 提交本轮改变的字段，保留未知值、未编辑项和继承语义。全局与实例覆盖必须区分，说明重启/下次启动/游戏退出后生效。参数建议先读取实际 Java、版本、当前参数和来源；不按模型猜测加硬性启动门槛，不凭经验删除用户自定义参数。保存后回读有效值及覆盖来源。

后台工具返回 jobId 时继续观察终态，取消或预算耗尽则保留引用让玩家继续查看；不能把 queued、prepared、deferred 或冲突当作已应用。安装/更新沿用真实审核清单及陈旧检测。工具结果的成功/失败由执行器提供，模型文本不能修改这些事实。

### 7.2 运行时操作策略

首版提供“只读”和“允许操作”两种会话模式，默认只读，选择持久化于会话且随时可改。用户在聊天里明确要求执行操作，可对该次目标启用允许操作，宿主记录授权范围，不要求每一个普通步骤再确认。模式只控制调用执行，不能只隐藏工具描述。

只读模式阻止写入、启动游戏、提交作业及有副作用的第三方调用；`execute` 不是只读工具，不能借它绕过限制。允许操作模式中，目标内普通配置和可恢复操作直接执行；现有产品本来要求最终清单/覆盖/删除确认的动作仍呈现相同实质确认。确认绑定精确目标、参数和状态指纹，变化后重新审核；模型或技能不能替用户点击确认。此规则用于正式软件运行，不为本次开发工作增加批准关卡。

现有 `ReadOnly/Destructive` 标记需要结合实际工具行为核对；第三方 MCP 的 annotations 仅是提示，不能单凭其自称只读开放操作。当前产品不开放第三方MCP注册。停止、执行前和实际分派三处检查授权/回合状态；首版工具串行，不并行修改同一实例。

首版不向模型提供通用 shell、无范围文件写入或动态代码执行；通用文件/网络能力通过随应用内置的 MCP 接入，不另外自建一套文件工具与搜索提供商适配器。内置MCP为自有进程权限边界，不能宣称只读模式等于 OS 沙箱。工具输出、日志、服务端描述均视为数据，不能作为新增授权。

### 7.3 可开启的本地文件访问

文件访问与会话“允许操作”分开配置：`disabled`、`read_only`、`read_write`，能力默认开启、读取模式默认为 read_only；当前数据根为固定 read_write 授权，App当前包的数据目录为固定 read_only 授权，用于日志诊断；两项不可编辑或删除。额外文件授权根初始为空，不因默认开启而扫描全盘。玩家在全局设置通过目录选择器或手工路径增加授权根，界面显示目录与模式，可持久保存并逐项撤销。聊天内需要目录时可给出简洁的范围选择入口；授权根由用户选择或确认，模型不能自行扩大范围。用户已开启的范围内普通读/搜索不再逐项确认。只读会话叠加 read_write 文件授权时仍只能读，写入须同时满足允许操作模式。

文件读写随应用内置经过核验的 MCP，可复用符合许可和验收要求的社区实现（例如 MCP 官方参考 Filesystem 服务），由统一 MCP 客户端发现其真实工具，不要求第三方采用启动器自定的工具名。需要支持的行为为：按根内相对路径列举、限定模式/目录搜索、分页/按行读取文本、新建和基于预期哈希的局部 patch。写操作用临时文件与可恢复替换；覆盖漂移返回冲突并重新读取，不盲目覆盖。首版不提供递归删除、任意二进制编辑或运行文件。无法解码/过大文件返回类型、大小和可选读取策略，不静默丢字节当全文。日志和配置脱敏后再送模型，保留行号/文件修订，显示读取范围而非伪造全文。

当前选择Rust文件MCP的真实schema与编辑/搜索引擎，但不让它直接写玩家目录：Core钉住原文件最终身份，严格解码/脱敏后提供有界私有快照，原生服务的cap_std约束快照根；预期原始字节hash、严格匹配/换行、备份与最终提交归Core。`rootId/expectedSha256`是薄宿主参数，不重新定义一套文件工具。单文件/目录预算、真实本地Windows范围、并发替换非通用CAS的边界见托管工具说明，不声称上游直接write_file天然具备这些保证。

选用的文件 MCP 必须以实际实现和运行验证证明路径范围约束；宿主在每次分派前检查当前授权与参数，文件服务内部按实际规范化路径、大小写/分隔规则和最终文件身份核验根范围；junction/symlink/重解析点不能越过授权根，读取与写入都要防止检查后目标替换。未知目标明确拒绝该次访问，可添加所需目录；不能以当前工作目录或字符串前缀判断授权。所选目录不是整个 OS 的沙箱承诺。产品秘密存储、模型/MCP凭据和账号 token 不通过文件工具送入模型，即使被宽目录覆盖也应按实际凭据路径排除。

能力与范围冻结为回合快照，同时每次分派叠加当前撤销状态：玩家完成所需目录/模式配置后，原先等待该配置的目标自动接续并记录新的授权修订，不要求再点击“继续”或重复发送问题；未等待配置的活动调用不静默扩大范围。关闭/收窄立即阻止尚未执行的读取和写入，取消正在进行的可取消读取；已读入但未发给模型的结果在撤销后丢弃。已经发送给模型的数据与已经原子提交的写入不能撤回，记录实际状态，不声称撤销等于回滚。事件记录文件引用与读取/变更范围，不额外把文件全文复制到普通诊断。

### 7.4 可开启的网络访问

网络能力为独立开关，默认开启，关闭时仍可普通模型对话；这个开关控制助手主动检索/读取和会话内在线内容工具，不等于切断所选模型 API 本身。设置中显示数据接收方，默认支持公开网页访问；不提供常驻“本机服务地址”白名单表单。玩家明确请求某个本机/局域网URL时，按该请求就近展示目标地址/端口与确认，授权只绑定本次请求，不自动成为其他请求的常驻授权。文件与网络可分别关闭，不自动互相切换状态，网络开启也不自动给予文件权限。

网页检索与读取通过随启动器提供的网络 MCP 使用，首装即可调用，不要求玩家安装程序、填写搜索端点或提供检索 API key；工具组件、运行依赖、连接与必要服务配置由产品负责。检索应返回标题、URL、摘要和可用的来源时间，网页读取应返回正文、最终 URL 与获取状态，各实现以真实 schema 为准。可复用符合许可和发布要求的现有 MCP，不另设“检索服务”页面或搜索提供商适配体系。默认检索后端必须合法提供无需玩家配置的路径；具体实现/后端在 S3 落地时核验并记录版本、许可、可用性与成本承担，不能将需要玩家自备密钥的 Brave 等候选直接当作默认方案，不在客户端嵌入可提取的共享供应商密钥。MCP目录为产品固定内置项，不开放第三方注册。离线、限流或上游失败明确呈现并保留普通聊天、已有来源和文件能力，不伪造搜索结果，也不把失败转成“请安装 MCP/配置检索”。

当前默认检索为Mwmbl明确匿名开放的v2查询API，复用固定DoH MCP的真实`doh_fetch`；公开网页另用固定网页MCP的`web_scrape`。API固定目标/查询/频率、服务及结果许可/引用、实际拨号代理、上游失败和截断边界见托管工具说明。DuckDuckGo Lite虽曾实测有结果，但robots禁止相关路径，已不作为默认工具开放；不把README许可或HTTP成功等同于搜索服务使用许可。

优先复用 Modrinth 等真实内容目录查询模组、兼容版本与依赖，通用网页用于补充文档/发布记录；默认 CurseForge 在线仍无 provider，不因“网络已开”擅自恢复 CF key/网络能力。会话内在线目录查询和第三方联网工具同样受网络能力调度策略约束；MCP 独立进程是否自行联网不由本开关保证，按其自身权限明确说明。开启能力可持久保存，范围内正常请求不逐条确认。

访问策略必须基于实际操作效果分派，包括 `execute` 转入的 typed 操作，不仅检查顶层工具名称；对会话内 Core 在线查询、下载与本地文件访问传递同一调用范围，避免换一个工具别名绕过关闭状态。这是 AI 回合的能力策略，不改变玩家手工使用内容搜索、下载安装等普通启动器入口的权限与可用性。

对默认支持的网页 MCP，核验其请求行为满足：网页请求限 HTTP(S)，不执行页面脚本、不携带浏览器 cookies/模型密钥/本机文件，不跟随重定向跨到未授权地址。每跳按实际解析地址检查 loopback、私网、link-local 与云 metadata 地址；互联网授权不隐含这些访问，玩家指定的本机服务必须有明确地址/端口授权并在调度时核对。超时、响应大小、重定向次数与内容提取有界，附件不自动下载到实例；实际安装继续走 Core typed 流程。

“看看服务有没有更新”先确认用户指定的是哪个软件/模型服务，读取其真实当前版本（来自已有健康/版本接口或已授权文件），再查官方发布源，区分稳定/预览和发布时间；找不到当前版本只能给出最新发布事实，不能断言已落后。查询不等于下载安装或重启服务，后续修改沿现有操作范围。最终回答引用来源和查询时间，搜索摘要不能冒充完整发布说明，也不能把网页指令当授权。

网络关闭/地址撤销立即阻止新请求并取消在途可取消请求，待发送模型的数据重新核验授权；已到达第三方的请求不能撤回。工具卡保留查询、访问主机、来源、时效、失败/部分结果与恢复入口。开启文件和网络不自动把整个本地目录上传，只有当前任务按需读取的内容才进入选定模型。

## 8. 固定内置技能与 MCP

产品随包提供启动器技能、文件和网络MCP，Core管理实际连接、工具发现、取消和生命周期；内置启动器工具直接调用Core业务，对外MCP由独立CLI包装同一Core工具契约。App不展示MCP或技能设置块，不提供新增、启停、编辑或移除；Core有效配置和加载路径忽略旧外部注册，修改请求显式拒绝，读取不擦除旧文件。内置依赖自包含，不要求玩家安装Node/Python。

技能使用SKILL.md元数据和正文，按需读取附属说明，不执行脚本。核心启动器技能每轮加载，其他内置技能通过skill_read按需读取，遵守有界读取和路径范围。技能和工具输出均不能增加执行权限。

每轮固定实际工具目录与来源；握手或个别工具失败不阻断普通聊天，已发出的写调用断连后按未知效果处理，不自动重放。收尾只关闭当前宿主拥有的子进程。外部客户端安装启动器MCP与内置AI扩展配置是不同职责，见下节。

## 9. 对外技能与 MCP 安装

安装器与模型无关；未配置 AI 服务也能给 Codex/Claude Code 安装启动器能力。首版只管理产品自己的技能目录和命名为 `rodel-minecraft` 的 MCP 条目，记录客户端、目标范围、写入路径、内容版本/哈希及恢复信息。

用户选择客户端后，检查可执行文件和用户配置根，允许手工指定。安装前展示技能目录、MCP 服务名称、绑定数据根及启动器可执行路径，用户点击安装后一次完成。App不携带CLI；选择独立发布的完整CLI目录中的rodel-mc.exe，登记直接引用其绝对路径，不复制二进制。预览冻结程序hash及绑定，替换或移动CLI后重新预览并连接核验。

客户端适配优先调用其已安装 CLI 的用户级 MCP 管理能力；技能复制到该版本官方支持的用户级技能目录。配置路径以环境覆盖与客户端实际版本为准，不能假设 Codex 与 Claude 共用路径。官方阅读入口见第 14 节；实现时确定并记录支持版本和实际路径。CLI 不存在时仍可独立安装技能并导出 MCP 配置说明，不报告 MCP 已注册。

安装/更新必须先读当前内容，保留其他 MCP、用户设置、未知字段与人工技能文件。旧条目完全属于本产品时可更新；同名冲突或已被用户修改时展示差异，只在明确选择替换后写入。解析失败不得覆盖原配置，提供可复制的手工配置。多文件操作有可恢复记录，部分成功逐项报告和重试，不能假称跨外部 CLI 操作是原子事务。

移除只清理仍匹配本产品记录的内容；玩家修改过的文件/条目保留并说明，不递归删除整个技能根。数据根修改重启后标记旧绑定需要更新，不能静默切换外部客户端操作的游戏数据。外部客户端的授权和执行规则由它自身负责，不把内置聊天的权限模式宣称为外部 MCP 的隔离。

## 10. 应用结构与宿主协议

### 10.1 依赖与文件职责

| 位置 | 负责 |
| --- | --- |
| Core `Application/AI` 与 `LauncherClient.Assistant` | 统一AI API与真实执行：配置、凭据、会话/历史、状态/技能、权限、恢复与编排；默认进程内，不是独立服务转发壳 |
| 内部 `Rodel.MinecraftLauncher.Assistant` 类库 | Core独占使用的提供商上下文、五协议/SDK/SSE、签名续传与通用MCP传输；无Core反向引用，不公开产品入口或独立发布 |
| App `Features/Assistant` | 页面、状态协调、输入草稿、会话列表、工具/确认呈现 |
| App 设置功能 | 服务/模型、内置 MCP 状态、第三方 MCP 管理、技能和外部安装表单；配置通过 Core 应用门面提交 |
| `Rodel.MinecraftLauncher.Cli` | 唯一CLI产物rodel-mc.exe；功能处直接绑定typed Core API、MCP同源schema/结果；ai后台也是同一EXE/同一Core |

CLI与Sprout均仅引用Core，Core引用内部AI模块，工程无循环。普通模型/会话操作默认在Core当前进程完成；只有CLI为host_owned跨命令存活显式选择同一EXE后台模式。内置工具直接调用Core，独立CLI提供对外MCP与显式后台宿主；App不依赖或打包CLI，AI模块仍是Core内部依赖。

Core `AiRuntime`统一持有模型执行、会话与恢复，`AiProviderService`读取冻结配置/凭据并调用内部AI协议帮助；`AiHostClient`仅是显式CLI后台模式的私有传输。首次工具回合真实初始化/发现产品MCP并消费同源structuredContent，不复制schema/token映射。当前九只读工具与两个技能读取工具开放，第三方annotations不自动受信。Core进程与CLI后台之间有跨进程生成/会话操作租约、运行者PID/启动时间与取消信号；不能误恢复活回合或把取消当回滚。MCP缺损独立记录，普通模型对话仍可用。

### 10.2 首版宿主连接

Core默认无需管道。CLI明确选择内部后台模式时，才使用当前用户Windows named pipe的版本化协议，并核对版本/用户/数据根/请求ID。进程内Core与后台Core共享执行租约及会话修订，不因换入口而重复生成或覆盖状态。

首次使用按需隐藏启动宿主，启动参数仅含非秘密发现信息；凭据按引用在宿主读取，不在命令行传递。握手/消息大小/读取队列有显式上限，大工具结果使用分页引用而不是无界帧。协议帧包含 requestId、方法、版本；事件有 turnId/sequence，断连后能用游标续读持久事件，并用快照弥补过期游标，不启动重复请求。

允许多个客户端连接，按回合显式分配 client_owned 或 host_owned 归属；客户端身份含进程启动时间，退出只取消它拥有的回合，观察客户端断开不抢占所有权。同一数据根其他客户端忙时得到明确 busy 状态，可观察并按显式命令取消，不启动第二个写宿主。无活动回合且无客户端时宿主退出；独立 Core 作业和游戏不随之退出。宿主协议不作为公开远程网络服务。

**单次请求**：Core默认进程内，CLI唯一生成入口为`rodel-mc ai request`，可用`--service`显式选择连接，经Core选择内部后台运行时。后台传输仍有当前用户/版本/根/请求ID握手、2MiB帧、最多8连接、10秒握手与有界退出；取消只影响自己的前台请求，不卸载其他进程的推理资源。逻辑管道名rodel-assistant不是EXE或产品入口。

**多轮实现**：`rodel-mc ai chat create/list/show/send/turn/events/cancel`调用同一Core功能。CLI默认host_owned，--wait仅观察，--cancel-on-exit绑定真实PID/UTC；普通Core调用默认当前进程，生命周期由应用管理，未来App按client_owned取消并有界收尾。后台模式隔离提交者stdio，活跃回合不因无观察者退出。跨入口生成锁、运行PID/启动时间、取消信号与会话操作租约分别控制执行、恢复和修订。

会话目录 `ai/conversations/<id>` 下的 `events.jsonl` 追加保存整段对话。提交的用户原文与图片引用写入 `user_message`，流式文本、思考、问答、工具记录及最终回复共用同一个日志，最终回复随 `turn_finished` 提交。普通聊天、皮肤编辑器和游戏内 AI 共用 Core 写入路径。日志沿用模型服务密钥的脱敏规则。`conversation.json` 与 `turns` 保留元数据、运行状态、权限、幂等与恢复快照，模型私有协议状态仍由回合快照承接。

同一日志的读写共用 Core 文件租约。每条完整 JSON 行在刷盘后进入可见索引，`sequence` 按回合递增，内存字节偏移用于分页和续读。异常退出后忽略未完成的尾行，下次写入修剪该尾部并保留完整前缀。已写入的终态回复可恢复未提交的回合快照，未知效果不重放。改名、确认删除、JSON／文本导出及失败重试仍由 Core 门面提供。游戏会话保留原有进程结束清理规则。自动压缩与归档续读见第6节。

UI 的真实步骤契约见 [Core API](CORE_API.md)：turn/model、answer、实际 provider reasoning、tool 和 skill 分别有开始/增量/结果/终态，使用 conversationId/turnId/sequence/stepId/parentStepId 和实际 toolCallId 关联。`model_finished` 不等于 `turn_finished`，工具链可以继续；工具结果不由模型文字决定。技能正文按需读取，仅实际读取才发出skill事件，不伪造自动执行或独立“思考中”过程。提供商没返回思考文本/usage 就保持缺失，不借助手文本推造；reasoning_progress 只报告明确证据与观测阶段，finished.displayableContent 与可选 usage.reasoningTokens 区分“观察到推理”和“收到摘要”。每个回合保留实际服务修订、模型及已解析端点；协议 opaque 状态只对匹配的协议/模型/修订回传，不通过公开回合/事件接口导出。

### 10.3 逻辑 API 与 CLI

以下是目标操作语义，统一命令前缀为`rodel-mc.exe ai`。这是Core AI的终端入口，不恢复旧单次ai run或独立助手EXE。confirm、内置MCP repair、范围执行和integration等尚未实现的部分继续列为目标，不以帮助/HTML当完成；实际命令见ai --help。

| 应用操作 | CLI 命令族（新增） |
| --- | --- |
| 列表/保存/删除/测试服务、列模型、设默认 | `service list/show/save/remove/test/models`、`model default` |
| 新建/列表/读取/改名/删除/导出会话 | `chat create/list/show/rename/remove/export` |
| 当前会话压缩前原文分页/单消息续读 | `chat archive CONVERSATION ARCHIVE --offset N --characters N --message-index N` |
| 发送、查询回合、游标事件、取消、确认执行 | `chat send/retry/turn/events/cancel/confirm` |
| 技能目录、启用/禁用与检查 | `skill list/add/read/enable/disable/check` |
| MCP 配置、启用/禁用与连通检查 | `mcp list/save/remove/enable/disable/test`；后续内置 repair 不开放身份替换 |
| 文件根/模式、默认开关与请求级本机地址确认 | `access show/set/revoke`；会话开关为 `chat access` |
| 外部安装预览、执行、检查、更新、移除 | `integration plan/install/status/update/remove` |

助手前端秘密输入仅从隐藏输入、环境引用或受控 stdin 接收，不提供明文 --api-key。send 默认提交 host_owned 回合，--wait 仅观察，--cancel-on-exit 绑定真实客户端身份；步骤输出显式走 stderr，不污染 MCP stdout。前端和主线 CLI 都使用成熟参数库及直接处理器绑定，没有旧参数兼容层。确认绑定精确 review/指纹，不能只是无目标布尔值。

事件最少包含 `turn_started`、`text_delta`、`tool_started`、`tool_finished`、`job_progress`、`confirmation_required`、`context_compacted`、`usage`、`turn_finished`。每轮恰有一个持久终态；客户端按 sequence 去重，不把缺失事件自行补造成成功。

## 11. Sprout 页面与交互

完整流程 HTML 参照：[首次使用](../design/index.html?page=ai)、[演示配置](../design/index.html?page=ai&demo=1&theme=light)。由 GPT-6-astra 在审阅本规格后制作，并按用户最新反馈承接当前启动器外壳；覆盖下述流程与失败恢复，全部为浏览器内存模拟，不代表原生或业务验收。

遵循 [现行设计](../design/DESIGN.md#启动器-ai-完整流程)：AI 助手移入启动器主侧栏，与游戏、实例、内容及设置共用导航；移除右下角 AI 按钮和已放弃的独立下载页入口。AI 页面直接位于现有内容区域，保留同一个标题栏、头像、侧栏、背景处理和页面起点，不另造助手外壳。页头保留标题与通往全局设置的低强调入口，左侧历史与新对话，主列聊天记录，底部固定实例/模式/模型快捷选择与输入。背景、材质、方角、强调色和控件角色复用产品规范；不恢复独立下载页或新造右侧小表单聊天。

Enter发送，Shift+Enter换行；IME composition期间Enter只提交预编辑。普通聊天与皮肤响应中仍可发送，新消息显示排队中并提供立即发送和取消；立即发送由Core停止同会话当前响应并优先执行所选项，CLI复用`ai chat turn run-now CONVERSATION TURN`。输入footer保留独立停止按钮，由Core在同一操作内取消排队项并停止此会话的真实活动回合，客户端快照过期也不能漏掉刚开始的后续回合。CLI复用`ai chat turn cancel CONVERSATION TURN --cancel-queued`；不带该选项只取消指定回合，余下队列正常推进。切历史各自保存草稿，实例/模型切换只影响后续提交。示例问题只填草稿；hover/focus时文字向内平滑移动12DIP，条目外框、分隔线与命中区域保持固定。

文本支持可选中复制、段落、列表、代码块和链接，首版 Markdown 不执行 HTML、脚本或代码。流式更新合批，不能每个 token 重建整页；玩家向上滚动时不抢回底部，提供回到底部入口。后台事件不能抢焦点；旁白按阶段或完整片段播报，不逐 token 打断。

窄窗保留主对话列，历史通过显式入口访问；800×560 DIP 下输入、发送/停止与返回均可见，仅记录和历史列表滚动。工具详情与真实错误可展开，保留长文本复制/导出；进行中/失败/部分回答各自明确，不能用固定进度或“思考中”掩盖实际错误。

全局“设置 → AI 助手”为单一页面，取消原来的五个页签；同页按模型服务、文件与网络、技能、MCP工具、外部AI工具依次组织，页面标题、分组和正文一起滚动，无局部列表滚动。全局搜索直接定位相应区域；从聊天/错误快捷入口进入设置时定位原目标，返回保留对话与草稿。

可折叠设置统一使用自定义样式的 Sprout `SettingsExpander`，不各自画独立箭头/折叠状态；HTML使用同几何和交互语义的设计对照组件。模型服务组默认展开：头部图标、名称与次级地址，右侧刷新/编辑/删除图标；组内模型行显示名称，仅名称与标识不同时补一行灰色标识，编辑/删除辅助图标悬停或键盘焦点时出现；底部单一“添加自定义模型”文字入口。刷新打开模型勾选并保留自定义模型和未改动记录的稳定身份，取消不提交，不新增重复服务。收起只改变显示，不影响服务可用性。模型行没有能力标签或人为能力门槛。

文件/网络默认开关直接展示，独立于模型；访问目录收进 SettingsExpander，展开后管理目录与读写范围。技能列表与第三方MCP列表也使用同一SettingsExpander，标题保留名称和简短概要/数量。内置MCP作为已提供的工具直接展示；外部客户端单行提供安装或按需管理入口。常用设置用共享行表面，低频列表渐进展开；只有失败或未完成才显示简短问题及恢复操作，不堆常驻状态标签和说明段。头部命令控件保留真实点击/键盘/无障碍身份，不把按钮放到仅渲染的view中冒充可操作；原生按Player已核对的`Content(Control)`/`ItemsFooter(Control)`路径接入。保持现有启动器材质、方角与主题，不照搬其他产品配色。

聊天模型快捷选择继续直接展开按服务分组的全部模型列表，选择即作用于下一轮，不弹出模型选择对话框。

输入区聚焦高亮覆盖整个 composer（上下文选择、文本输入与底部发送区），文本框不再单独画焦点边框；焦点进入锚定下拉时保持整个区域高亮。输入区采用轻量的实例/模式快捷选择，ComboBox常态边界、底面与阴影弱化，焦点/展开时才清晰表达交互。文件/网络分别使用纯图标按钮，默认开启高亮，以 aria-pressed/无障碍名称表达状态；关闭后回到低强调状态，设置中提供完整访问范围。底部只显示“Enter 发送消息，Shift+Enter 换行”，不常驻发送目标、草稿说明、缺模型教学或能力说明；真正无法发送的原因放在相应页头/空态/字段错误处。

消息区以玩家与助手的消息为主体：按亲密性组合消息与引用，所有正文保持对齐，复制/工具详情等使用重复一致的低强调语汇，主要对比留给回答与真正需要的操作。常规技能加载不显示独立技能条/卡片；每条回复的普通工具过程默认汇成一条细小、折叠的操作摘要，按需展开文件范围、网页来源和结果，成功后台任务也归入过程，不在回答后常驻独立任务块。引用来源在回答附近保留简洁入口。复制等辅助操作仅悬停/键盘焦点时以平图标出现；普通完成回复不附加“接续提问”或重发按钮。失败可以有简洁的文字重试，必要审核确认与进行中/失败后台任务操作保留实质功能，但不为每条状态堆方块按钮或重复边框。撤销立即更新可执行状态，模型文本不能覆盖执行事实。

无服务/无模型/服务不可用/无历史/缺实例/工具不可用分别显示针对性状态。公开文案与无障碍名称使用 Sprout Resources，稳定 AutomationId 不取翻译文本。

## 12. 错误、诊断与发布

新增错误至少覆盖宿主缺失/协议不匹配、服务不可达、鉴权、限流、模型不存在、能力不支持、上下文超限、无效工具参数、权限不足、陈旧确认、效果未知、记录不可写和安装冲突；保留上游状态码/请求 ID 的脱敏诊断，界面显示本地化摘要和实际恢复入口。

诊断默认只含版本、阶段、耗时、错误码、实际 usage 和经处理的调用信息，不默认导出全文聊天、私密参数或 provider opaque 状态。聊天导出是玩家独立操作，不冒充云端数据删除；产品不承诺提供商零留存。关键秘密跨文本增量分片也应遮蔽，不能只逐片正则处理。

正常App仍为packaged MSIX/NativeAOT，用户入口仅App与CLI；AI内部类库随Core编入调用端，不另发布AI Host。CLI主入口是rodel-mc.exe，固定组件/许可证随Assets/AiMcp发布，不要求玩家安装外部运行时。MCP工具服务无需配置模型；Core普通模型对话无需产品CLI在场，只有实际工具/显式后台场景需要CLI。AI服务失败不能阻断普通启动功能。产品不依赖本地验证工程，协议/源生成与裁剪兼容必须实际执行验证。
