# 运行限制与恢复边界

限制必须服务于实际可执行性或数据安全，不能由未知信息、兼容建议、可选服务故障或局部读取失败凭猜测建立。本文只说明当前契约，不记录修复阶段或验收流水。

## 可恢复状态

| 场景 | 应有行为 |
| --- | --- |
| 已登记实例缺版本摘要 | 允许普通启动进入Core按需准备；如实说明缺失摘要。空版本或不可读的必需登记仍可能无法构造请求 |
| 只修改Java、内存或离线身份 | 校验并原子写入实际编辑字段，保留未知字段、手工JVM参数及无关设置。物理内存建议不作为保存门禁 |
| 托管Java引用失效但有显式Java覆盖 | 保留原引用及JAVA_RUNTIME_UNAVAILABLE诊断，显式覆盖优先；不偷偷改用另一Java，也不改持久选择 |
| 单个内容或附加文件不可读 | 保留具名读取警告，继续显示可读项和独立远端结果；不伪造哈希或可读状态，不吞取消或实际写入错误 |
| 终态任务无活动会话 | 不把任务完成记录当作游戏仍活跃；按目录、registry及完整进程身份核对，确证已退出时保留原因并允许适当恢复 |
| 可选目录、平台或推荐服务失败 | 对相应操作给出降级或明确错误；已有运行文件、离线身份和手工配置仍有可用路径 |

## 必须保留的保护

| 类别 | 依据与恢复路径 |
| --- | --- |
| 必需启动信息 | 无有效版本ID、继承环、不可读的必需元数据、缺少mainClass或最终进程创建失败时，不能执行该请求。普通在线启动可补齐已知缺失文件；plan/offline不承诺下载。未知扩展字段或加载器名称本身不是拒绝理由 |
| 明确选定的执行文件 | 失效的托管选择不能静默替换成其他Java；允许显式覆盖或编辑修复。版本探测失败及推荐版本不同应解释，不能变成硬白名单 |
| 同实例活动游戏或任务 | 通过游戏目录、PID、StartTime、monitor及registry保护实际在用内容；Core统一区分游戏、普通任务、内容下载及任务活动未知，`INSTANCE_BUSY`保留具体原因与任务ID，App不另造判断。内容下载可在游戏退出后继续，提示引导查看下载列表而不误称游戏仍运行；相关身份不完整时明确不确定性。无关目录的坏记录不得造成全局禁用 |
| 冻结审核与事务 | 版本、依赖、来源或目标漂移后重新审核，防止确认A却写B。取消/失败保留旧文件、禁用状态及恢复记录；不能覆盖外部后续编辑或将恢复失败报成功 |
| 世界锁与恢复所有权 | 尊重session.lock、活动检查、备份一致性、原文件摘要及目标归属；解除实际占用、改目标或选择正确备份后可重试，不要求删除玩家世界 |
| 路径与发布冲突 | 防止归档越界、源目标包含、同名覆盖、共享依赖污染和误删被引用Java。独立暂存及原子发布失败应限定当前操作 |
| 自动匹配能力 | 无可靠上游、存在pin或依赖修复证据不足时，不猜测更新或强制修复；保留原内容的管理和启动路径 |

## 入口责任

CLI/MCP复用同一[Core调用能力](CORE_API.md)，不得新增入口专用白名单或复制业务。App负责真实字段语法、当前状态与操作生命周期，不以摘要错误替代Core实际准备判断。

原生UIA可见性不是游戏兼容条件。窗口隐藏/恢复应由框架在真实显示操作后同步语义，不能通过忽略Offscreen、虚构可操作性或改变窗口尺寸掩盖错误。

相关实现：[启动](../src/Rodel.MinecraftLauncher.Core/Application/LauncherClient.Launch.cs)、[设置](../src/Rodel.MinecraftLauncher.Core/Configuration/SettingsService.cs)、[内容](../src/Rodel.MinecraftLauncher.Core/Content/ContentService.cs)、[世界](../src/Rodel.MinecraftLauncher.Core/Worlds/WorldService.cs)、[版本解析](../src/Rodel.MinecraftLauncher.Core/Launch/VersionResolver.cs)。

## 验证边界

源码、合成文件、受控HTTP、Java夹具、NativeAOT CLI、正常packaged App及Minecraft运行分别判断。进程启动、客户端初始化、SLP或一条成功请求都不能证明所有版本、完整游戏就绪或服务器已加入。

正式CLI回归入口见[测试说明](../test/README.md)。新增硬拒绝须能解释实际执行或数据保护原因，不能以文档描述代替所需验证，也不承诺任意损坏状态和第三方输入都能自动恢复。
