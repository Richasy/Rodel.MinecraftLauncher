# Design Reference

本目录维护启动器当前设计规范与可交互HTML原型。原型仅使用模拟数据，不调用Core、不读取玩家目录，也不能作为实际安装、网络、模型或游戏运行的验证结果。

全局设置八分类已统一为 AI 设置同款卡片与展开组，含 AI 新对话默认模式（允许全部 / 安全模式，默认安全模式）。HTML 使用模拟数据，不代替原生验收。

设置末尾另有只读的[关于此应用](index.html?page=settings&topic=about)：真实包版本、开发者的其他商店应用、GitHub 仓库／Issues、使用指南及同页平铺的项目／许可清单。关于页不设分类展开、组件搜索或二级详情；静态原型版本仅为示意。

## 阅读顺序

1. [设计规范](DESIGN.md)：页面职责、布局、主题、组件状态与原生实施约束。
2. [交互原型](index.html)：页面与状态的可操作参照。
3. [功能边界](../doc/ALIGNMENT.md)、[Core API](../doc/CORE_API.md)与[架构](../doc/ARCHITECTURE.md)：产品入口与真实业务契约。

指示优先。页面布局、分类、菜单、上下文入口与任务语义须与产品一致；具体材质和控件几何由原生共用组件承担，不逐像素追齐，也不以默认Fluent外观替换当前方向。

新增界面必须遵循[信息分组、对齐与提示克制](DESIGN.md#信息分组对齐与提示克制)：用共享边框、背景和统一文字起点组织区域，不擅自堆解释或提示。

原生Windows调用遵循[Win32互操作实施约定](DESIGN.md#win32互操作实施约定)：先复用.NET/框架能力，再使用CsWin32；不复制SDK已有ABI，不混淆拥有、借用及转交系统的句柄。

## 页面与交互

实例菜单在[实例交互原型](instance-management.js)与原生实现中将重命名／更换图标／创建副本直接放在一级，“游戏与工具／备份与导出／打开目录”提供二级入口；分割线隔开任务组与末尾删除项，仅删除使用critical字色，恢复保持普通字色。当前规则见[设计规范](DESIGN.md#提示文案准入)，原型只模拟展开／键盘与任务入口。

首页本地实例列表提供重命名／更换图标／删除的简单右键菜单，与实例页共用原生命令及操作弹窗；右键未选中条目不改变当前实例，操作仍指向右键目标。服务器收藏不套用此菜单。

[实例截图交互示意](screenshots.html)对应世界之后的截图页：实例级统一16:9缩略图图库、搜索/排序、单击选择／双击外部打开、Ctrl／Shift／Ctrl+A、accent描边多选和右键/长按菜单；删除确认提供回收站／直接删除／取消三个按钮。预览允许居中裁切但不改原图，卡片等高，滚动末尾保留24 DIP内容间距；单行标题溢出提示、不显示文件大小，不按世界分组、不内置看图器。此独立示意页的相邻分类只展示位置，使用既有壁纸作为样本，不读写玩家图片或剪贴板，也不代替实际Core/CLI与原生验证。

新增[联机迷你状态窗规格](DESIGN.md#联机迷你状态窗与等待加入)：320×64，8 DIP视觉内距、48 DIP图片、标题／状态组垂直居中。仅活动联机的房主在主窗最小化／托盘且设置允许时显示，与主窗互斥。已按HTML实现原生窗口、明确的可加入状态、存档缩略图及等待朋友空态。仓库外HTML仅用于审阅，不作为产品运行依赖。

房间页使用合并后的自然高度房间头：左侧图片／房间名／身份，世界名与房间名不同时才补充显示；右侧状态／操作，实际就绪时在其下方显示紧凑邀请码。下方直接进入独立滚动的成员／环境两栏。复制操作在输入框内部尾部，分割线贯穿容器；成员空态按实际可见区域居中。文字按钮由内容与padding测量，不固定高度。页头陶瓦署名及info入口在尾部，详细几何见同一设计规范。

[联机生命周期体验方案](MULTIPLAYER-LIFECYCLE.md)明确开始与游戏启动串联、退出世界自动结束、正常退出观察、仅停止联机及同世界断线恢复。Core、CLI与原生已接入，不由接线完成推定整个兼容矩阵已实机验收。

[联机房间原型](index.html?page=multiplayer)提供交互示意。侧栏独立“联机”，要求房间页有自己的布局：成员、邀请、环境与恢复为中心，直接选用首页已有实例；首页仅有活动房间返回，实例菜单提供“用此实例创建房间”。顶部模拟场景可查看创建／加入、环境差异、房主／加入者、准备中断、断线、外部房主、世界关闭及多个游戏。规则见[联机设计](DESIGN.md#联机房间交互原型)；HTML里的房间码与整合包为模拟，不代替Core、CLI及原生App验收。

联机使用创建／加入持久Popup，并在同一Popup完成差异与环境准备；关闭取消弹窗持有的当前准备，保留草稿及可恢复数据，重开后显式继续。页标题旁小字“陶瓦联机”，不设品牌footer；房间结束／离开／取消归房间标题右侧，两栏分别滚动，文件差异使用设置页同款Expander。连接记录从正文移除，右侧分享整合包下方可导出本方记录；原型下载标注模拟来源的TXT快照。房主成员上方显示可靠取得的当前世界名／开放状态，加入者没有资料时不猜世界。只保留陶瓦名称，不展示其他产品；本机头像与远端单人占位分别呈现，实际远端头像需额外可靠身份／皮肤信息。按当前单会话接口呈现一个活动房间，结束后可再开。[房主房间](index.html?page=multiplayer&room=host)可直接查看。

加入只识别原生陶瓦房间码，可从文字提取有效码；自定义“完整邀请”及其环境字段已移除。整合包文件为独立可选输入，不能从房间码得到。原型校验已对齐所核对解析器的提取／规范化／校验规则；符合规则的样例仍是演示码，不对应真实在线房间。

房间码现为正常单行输入。[没有实例场景](index.html?page=multiplayer&room=no-instances)在同一Popup提供创建游戏实例／导入整合包，完成后回到原草稿并选中新实例；准备支持取消、重试；关闭取消当前准备，重开后可显式继续。只有房间码时需向房主确认游戏环境，不自动猜版本或传整合包。库存、创建与下载均为浏览器模拟。

创建游戏实例／导入整合包现为有、无实例都提供的共同入口，有实例时另外选择已有环境。任务footer统一按ContentDialog规则：单按钮右侧半宽、仅文字，创建／加入／对齐／准备各阶段一致；标题及正文操作保留各自图标。

创建Popup已移除步骤条；房主新建实例使用可搜索的完整官方版本目录，加入者按整合包或先手动确认的房主版本锁定创建，房间码不提供版本资料。房间“游戏环境”的内容图标可直达该实例的模组页，切页保留房间。默认托管流程调整为[进入世界后自动开放](index.html?page=multiplayer&room=waiting)，失败可重试，未适配版本保留手动路径；实际Core已接进入世界后的开放与手动回退；HTML只模拟流程。

联机页面与弹窗已清理重复状态卡、通用说明、保留数据的重复保证及模拟操作Toast。任务弹窗没有通用info，联机页头只保留署名与存档位置；当前错误所需的手动开放路径、实际进度和待校验文件仍在所属位置显示。

版本分类标题使用小号Muted文本，不可选择或键盘停靠；原型共享一份静态内存目录，重复展开／筛选不请求网络。真实App复用Core的6小时共享缓存与并发合并，普通重开不强制刷新。普通新建、联机新建与房主版本确认共用Controls/Versions，HTML共用game-versions.js；正式版／快照等分类标题不参与选择。房间页已移除重复展示摘要的“查看环境”，保留实际模组管理与房主分享操作。

[准备中断](index.html?page=multiplayer&room=download-failed)把单文件恢复放进中断条目，使用明确的“选择本地文件”；选择单个JAR后仅标记待校验，可更换／取消，footer继续准备统一处理。现有Core的批量manualDirectory不是这里的单文件选择器，真实接线需Core暂存／声明哈希核验及审核提交；原型没有读取或校验JAR字节。

种子探索器的[实例世界地图设计](seed-explorer/DESIGN.md)Core／CLI／Sprout已接入实例／世界读取、存档实况优先与外围原版预览、玩家定位，以及只启用已安装实例版本的完整Java版本目录。原版生成与旧运行时定位按实际API形态扩展并完成代表版本实跑，不把代表样本外推为每个历史快照均已实测。审阅HTML保存在仓库外、使用固定样本／模拟数据，不参与产品构建；整合包生成继续后置。

[材质与光影](VISUAL-PACKS.md)区分安装库存和游戏真实选用：材质可叠加并调整优先级，光影单选；内容页直接操作，Core / CLI / MCP 共用实际配置和指纹保护。

皮肤编辑器使用[独立窗口原型](skin-editor/index.html)，默认手动编辑。右栏可拖动边界调宽；AI只简化模型选择及输入操作，直接编辑当前皮肤，不显示审批或候选；完整聊天消息、思考和流式回复保留，输出间的工具调用合为一个Expander，展开显示具体步骤与读画目标；无历史时显示空态。原生无工程时先显示左侧模板网格/右侧命令与近期工程；新建工程统一人物与空白披风模板，固定卡片读取打包的高清抗锯齿预览图片，模板与近期列表分别在可用高度内滚动；单行标题栏容纳纯图像logo、独立工程菜单与默认折叠的工具选项、独立镜像开关、撤销/重做与导出。主画布切换3D/平面，独立UV小窗可同时编辑；左键绘制，Ctrl＋左键拖动平移模型视图而不改变缩放、旋转或选区，Alt拖动旋转或平移。颜色、可编辑色板、RGBA图层缩略图与可回溯历史服务手动流程，左下色块就地打开HSV选色浮层；AI通过右侧页签直接修改当前皮肤。[皮肤UI/UX规格](skin-editor/DESIGN.md)明确原生接线与现有Core/MCP的差距，[社区依据](skin-editor/RESEARCH.md)记录固定源码与取舍。它仍是设计参照，不恢复已移除的产品HTML查看器。

AI聊天的工具与思考共用同款非动画展开头，皮肤回答不另加小标题或复制按钮。输入区通过一个图片图标按钮选图、Ctrl+V识别剪贴板图片，不另设粘贴按钮；最多3张PNG/JPG/WebP参考图，草稿可移除、发送后随用户消息保留；原型仅在浏览器内展示，实际图片输入与持久化由Core负责。

AI欢迎建议增加180ms hover/focus内缩动效，输入上方使用依次跳动的三点。响应中可继续发送和取消排队，历史以badge表示响应/待回复/排队/未读；展开头尾侧显示用时。`ask_user`只显示一张无计时的问答卡，问题与回答分区，回答使用用户消息底色，跳过保留独立状态。原型输入“排版”“表格”或“Markdown”可查看标题、列表、引用及表格示例；该示例与队列均为浏览器内存模拟，真实顺序、取消、用时与已读持久化以Core和原生验收为准。

默认人物使用原创像素的“经典蓝衫”基础模板；新建提供经典蓝衫、Alex 风格、日常白衫、基础人形、空白素色五种真实预览，可分别选择标准 / 细手臂与64 / 128纹理，创建才替换作品。Alex 推荐 Slim，玩家手动选择模型后不再随模板切换。原型与原生均已接两种模型、两种尺寸的编辑与PNG导入导出；原生复用Core共享草稿、图层及完整历史。128用于HD纹理，Java账号上传使用64；账号应用与皮肤AI面板不因手动编辑已接而完成。

色板初始提供五套不同风格的16色预设，预设也可删除；选择器旁加号直接提供空白／参考图新建。参考图上方工具行支持缩放、平移、复位及带像素放大镜的精确取色，下方预提取最多16色，合并感知近似色后按色系及明暗规整排列，再由玩家增删，确认才保存草稿。管理页仍以名称和色块为主，复制／删除归菜单，名称行内编辑、HEX有效输入直接生效、网格尾部加色；图片只在本次草稿中保留，不上传或写入工程。

披风独立作品和共享人物搭配见[当前规范](DESIGN.md#披风独立作品与搭配预览)。空库提供通栏 PNG 导入，有作品后使用同排 ComboBox 与上衣加号图标。人物与披风分别保存和导出。

皮肤图层支持同尺寸透明PNG新增为顶层，以及单层原始RGBA导出，服务披肩叠加与分享；既有完整皮肤导入/合成导出保持各自语义。原型文件操作仅在浏览器内存执行，不代替真实工程、历史、原子发布及原生验收。

原生已有首页、实例、内容、设置，任务进度、取消和恢复归原功能，不提供独立下载页。运行环境属于实例子页，Java管理属于设置。

主页及实例页的本地列表接受单个MRPACK/ZIP拖入，打开预填来源的整合包创建表单；服务器视图不接受。两处列表没有常驻拖入文案，只在接收文件时显示松开反馈。原型只使用文件名演示表单，不读取包内容或创建实例；实际识别、复制及缺件报告由Core完成。内容JAR继续先审核，路径、世界、壁纸及AI参考图片同样不附加常驻拖放说明，仅在接收文件时反馈。

参见[AI故障修复](AI-REPAIR.md)：Core、CLI/MCP与App已接入同一故障委托、专用工具、回退记录、新运行观察及既有ask_user。一次发起后自动诊断、执行范围内的可回退试验和验证，原故障再次出现时恢复无效试验。HTML仍为模拟参照，可用`index.html?page=ai&demo=1&repair=conflict`演示；`dependency/java/runtime/unknown`覆盖不同场景。原生只按实际初始化证据报告启动检查，游戏内隔离复现/自动化尚未实现，不能把原型中的副本复现视作已交付。

首页本地实例与服务器空态共用完整引导：分类、主标题与单句说明，左侧启动/配置保持禁用，不重复新建入口；对应列表为空时只强调右侧底部原尺寸的新建split button/添加button。首页与实例/服务器管理页共用无底板图标、短标题和操作提示的居中placeholder。已有目标仍按名称、运行摘要、配置划分文字层级，不把精简重复提示做成删光引导。

AI助手继续使用同一外壳；主导航在内容与AI助手之间提供“联机”，可见性由设置控制。[AI流程](index.html?page=ai)与[完整规范](DESIGN.md#启动器-ai-完整流程)是AI设计入口。原生对话/历史/输入区、全局AI设置（模型服务、能力/目录及外部接入）与相关表单已合入主项目；底部栏与首页壁纸名称已移除，内容区保持既有对齐原则。功能接Core typed配置、模型发现、会话事件流及审核接口，MEAI循环在Core运行，UI不复制驱动；不能把HTML模拟当作真实运行结果。

全局设置模拟有效编辑自动保存、校验与输入保持；首页和实例页的运行配置共用light-dismiss入口，无保存／关闭按钮，游戏桥默认开启；复制、恢复、删除等任务仍保留确认。账户管理轻触关闭，添加账户为绿色立体主按钮；实际游戏窗口可见后首页进度为100%。AI设置的右侧正文滚动，页头与分类固定，使用统一SettingsExpander，不设第二级页签。模型服务、文件/网络及目录、外部安装归全局设置；内置技能/MCP固定，不恢复其自定义登记表单。聊天返回后保留草稿和在途状态。

AI审批固定在输入框上方的紧凑横幅。安全模式使用批准split button，主按钮仅批准本次，菜单允许本会话内所有同名工具；切换权限模式会撤销授权。允许全部不再出现操作审批，冻结审核、实例及目录/网络范围仍由Core检查。查看详情才打开只读Dialog，关闭不作决定，详情阅读为可选。原型仅模拟这些状态，真实授权与指纹校验归Core。

内容页提供实例上下文、集中搜索、从文件添加、分类/行菜单、冻结审核和任务反馈。文件选择和拖入仅记录文件名，不读取或安装归档。世界管理与内容启停分开。整合包准备采用横向Popup，一次确认后自动推进文件、游戏/加载器和Java步骤；有序结果、当前loading及右侧参数/补件留在同一工作区，错误才暂停处理。缺件为单行卡片与尾端tag，页头“×”关闭，文字操作与无边框关闭图标区分。实例更多菜单的维护入口由`pack-maintenance.js`模拟本地/来源审核、冻结应用、回退与解绑；它是560px上限的紧凑单列，不沿用准备工作区宽度。真实HMCL、原生维护及在线能力不由示意推定完成。

Light/Dark/模拟高对比度沿用共用主题角色，壁纸槽独立。壁纸设计和可读性规则见[可读性设计](wallpapers/READABILITY.md)。原型中的AI响应、进度和任务记录均为交互示例，不代表产品能力。

## 预览

[外置账户设计](index.html?accounts=1&external=1&theme=light)包含LittleSkin、其他认证服务、角色选择及异常恢复。LittleSkin设备流应用未开通时直接转密码表单并预置地址；设备流可用时沿用授权码及并排的网页/取消操作。普通表单与错误页标题左侧均保留返回。其他服务同页填写地址与账号密码，一次登录自动读取服务信息。“预览流程状态”选中即展示完整虚构状态。[外置账户规格](EXTERNAL-ACCOUNTS.md)记录固定HMCL源码与LittleSkin授权条件。HTML不发认证请求，勿输入真实凭据；Core / CLI / Sprout已接入第三类外置账户。

[皮肤动态预览](skin-editor/index.html)从顶部“预览”打开手动关闭Popup，渲染区域零内距铺满Popup，关闭图标位于视图内部右上角；按MC标准人物步态循环预览当前浏览器合成，不修改工程。原生使用同一交互，原型不代替实际渲染、循环和包验收。

[实例图标选择](index.html?page=instances&theme=light)从每行省略号的“更换图标”进入，共28张透明方块图片，并支持真实本地图片解码和裁切（仅浏览器内存保存）。

[本地账号头像原型](account-avatars/index.html)提供28个正面方形像素头像（4批各7个）、默认史蒂夫、菜单缩略图与尾部类型提示，以及预制选择 / 自定义图片裁切 / 取消 / 保存流程。[图库](account-avatars/gallery.html)可查看全部素材，[流程规格](account-avatars/DESIGN.md)说明边界。微软账户保留在线图片、本地账户才可修改；原生已接入同一流程，账户菜单固定360 DIP并使用铅笔修改入口；重新登录状态使用Critical小字。

[首页服务器](index.html?page=home&target=server&theme=light)与[实例/服务器](index.html?page=instances&view=servers&theme=light)共用分段、收藏与连接流程，设计边界见[SERVERS](SERVERS.md)。[账户管理](index.html?accounts=1&theme=light)及头像菜单按[ACCOUNTS](ACCOUNTS.md)承接已认可设计；原生WAM登录、浏览器替代和错误恢复不由HTML推定通过。

原型为静态文件，无需npm依赖。在仓库根目录运行：

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

打开 <http://127.0.0.1:8765/design/index.html>，皮肤编辑器为 `/design/skin-editor/index.html`。已有服务时复用，不重复启动。AI可从[首次使用](index.html?page=ai)操作或[演示配置](index.html?page=ai&demo=1&theme=light)载入内存模拟；演示不读取凭据、不连接模型、MCP或外部客户端。壁纸选择与导入图仅保存于当前站点的LocalStorage/IndexedDB，不上传图片；皮肤自定义色板及当前色板选择使用本地LocalStorage，皮肤像素、绘图层和历史仍只在浏览器内存中，刷新重置。其他业务状态只在浏览器内存中用于评审。

顶部和底部评审工具不属于正式产品。按压、错误、运行和主题切换用于观察状态，不表示真实业务执行。正常消息没有接续按钮，授权或目录补齐后原等待目标自动推进；未知效果不能假称已应用或自动重放。
