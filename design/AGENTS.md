# 设计协作约定

- 修改设计或实施 UI 前，先读本目录的 [README.md](README.md)、[DESIGN.md](DESIGN.md)，查看当前 HTML 对应页面/状态。仓库根 AGENTS.md 与用户最新指示继续有效。
- 当前原型是用户认可的方向。保持布局、微立体材质、连续线条图标、列表密度、沉浸标题栏和完整 AI 对话页；不要重新设计成默认 Fluent 管理后台。
- 只维护当前规范、原型及其实际使用的资源；废弃设计及其生成提示、截图直接删除，不另设历史目录。不能用概念生成图替代当前可交互原型。
- 本目录只包含设计参照与模拟交互。不能把示例响应、任务百分比、实例内容或模型连接当作真实能力验证。
- 用户对截图中的具体UI问题提出修改时，同时修正当前实现并将可复用原则写入DESIGN.md；除非明确只要求记录，不以补文档代替改界面。底部双按钮平分宽度、说明文本Secondary、路径分组和浮层滚动条贴边适用于同类界面，不限于首次指出的页面。
- 新增状态先使用统一主题/组件规则，不靠逐控件覆盖。修改后核验相关页面、键盘操作、滚动边界和对齐，按变更需要同步规范，并在回复中报告实际结果。
- 实施原生 UI 时也要承接此规范；Sprout 直接引用 Core，CLI/MCP 只做适配。是否开始原生实施按用户任务授权，不因有设计基线就自动扩展范围。
