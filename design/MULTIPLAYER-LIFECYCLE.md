# 联机生命周期体验方案

本文件为认可并授权实施的体验契约。Core、CLI与原生已按此接线；材质、间距和组件沿用[DESIGN](DESIGN.md#联机迷你状态窗与等待加入)，不把目标矩阵等同于全部实机通过。

## 产品决定

一次联机围绕一个明确的游戏会话及一个世界展开。创建负责准备并启动，世界就绪后自动开放，结束负责联机与游戏共同收尾。临时网络故障在原会话内恢复，不等同于退出游戏。

房主主操作使用“结束并退出游戏”，正常保存并退出本房间对应游戏；同一个SplitButton的箭头菜单保留“仅停止联机”，让房主继续单人游玩。加入者主动离开使用“离开并退出游戏”，同一个SplitButton的箭头菜单可仅离开房间。动作文字承担解释，不再增加常驻说明、通用提示卡或每次重复确认。

这些结束方式由入口显式传给Core；不能把既有仅停止网络的后台操作或许可静默扩大为关闭游戏。关闭联机页、Popup、主窗或迷你窗不是同一个动作，分别遵守下文的所有权。

## 房主流程

1. 点击创建房间，在Popup选择已有实例。房间名默认取所选世界名，可修改；清空后主操作禁用。始终保留新建实例、导入整合包入口，共用版本组件和全局缓存。
2. 选择已有存档时展示真实缩略图和名称；最近一次有效选择可预选。需要新世界时打开游戏原生创建流程，不在启动器复制世界创建器。加入入口的版本受已确认目标约束，房主创建仍可选择全部支持版本。
3. 点击“启动并联机”。支持直接进入所选世界时复用既有世界启动能力；新世界或暂不支持直达的版本在游戏中完成选择。只有一个真实准备任务，取消停止Popup持有的任务，终态后才关闭，不留下后台准备。
4. 已有合适的运行游戏可复用，不重复启动。若同一实例有多个运行会话，明确选择本次游戏／世界，不自动取第一个进程。已有世界的动作使用“开启联机”。
5. 当前世界就绪后自动开放，保留游戏原有模式和作弊设置。实际监听端口与陶瓦均就绪后，状态才变为“可加入”，显示邀请及复制操作。

创建表单是草稿，不先建立一个空网络大厅。启动／选择世界期间展示准备状态，不显示“等待朋友加入”；只有实际可加入且没有朋友连接时才显示该空态。

## 加入者流程

填入陶瓦房间码 → 选择或准备游戏环境 → 点击“加入并启动” → 自动连接对应世界。网络已连接但游戏尚未进入时，呈现“正在进入世界”，不提前宣称已经入服。

有整合包时先展示实际摘要及必要变更，复用既有导入、审核、下载、手工补件和恢复任务。只有房间码时不能推断版本或模组，更不能假装已核验环境；让玩家选择已有实例或明确目标版本，不强制安装未知内容。临时下载中断保留已验证文件，继续操作复用任务，不重建实例。

已在正确目标游戏中不重复启动。已运行其它世界或不同实例时，不静默切换、退出或关闭；必要的操作明确标为“重新启动并加入”，只作用于玩家所选会话。远端暂不可达时，客人的游戏保留在实际断开页面，保留重新连接机会，不自动退出客人的游戏进程。已明确房间结束时停止重试旧邀请，保留游戏并允许换码加入下一场。

互通继续使用标准陶瓦码。整合包另行分享，不要求外部客户端识别私有清单、结束原因或安装相同的自动化组件，才能完成基础联机。

分享时省略的必需文件仍须带路径、哈希、大小和已知来源，接收端进入同一缺件补齐流程；不能仅因来源无法自动下载就丢掉要求。来源声明不等于出版方身份验证；无法识别扩展清单的外部客户端可读取随包提供的完整要求。

## 状态与操作

| 真实情况 | 呈现 | 主要操作与结果 |
| --- | --- | --- |
| 环境准备未完成 | 准备中及真实进度 | Popup提供取消，等待真实取消终态 |
| 本次新游戏仍在启动 | 启动中 | 取消未执行的启动；已生成的本次新游戏正常退出，不遗留后台进程 |
| 游戏已启动，尚未进入世界 | 进入世界 | 返回游戏；邀请不可用 |
| 世界正在开放／建立网络 | 正在开放联机 | 返回游戏；邀请不可用 |
| 世界及连接就绪、没有朋友 | 可加入；成员区等待朋友加入 | 复制房间码 |
| 正常联机 | 可加入；真实成员列表 | 返回游戏；结束并退出游戏 |
| 同一世界临时掉线 | 正在重新连接 | 保留游戏；有界恢复，必要时重试 |
| 房主退出世界、切换存档或关闭游戏 | 自动结束房间 | 关闭对外连接、收回邀请、释放资源、收起迷你窗 |
| 手动结束并退出游戏 | 正在结束；有真实证据时展示保存／退出进度 | 不重复提交；观察游戏退出及联机清理后完成 |
| 选择仅停止联机 | 房间结束 | 游戏继续单人运行，不再自动开放后续世界 |
| 仅关闭或最小化窗口 | 房间状态保持 | 不结束游戏、不停止房间 |

修订：结束完成后保留原房间工作区、名称、世界图片和实例，状态为“房间已结束”，直到新的创建／加入任务真正开始后再替换。右上提供创建／加入入口；打开、关闭弹窗或准备新实例不清空旧房间。结束中的事务及退出受阻仍按原流程收尾，不能提前当作已结束。再次开启是新房间，生成新邀请；原邀请失效、迷你窗收起，不自动公开后来进入的其它世界。成员分隔线仅在条目之间绘制，主列表与迷你窗Flyout均不在末项下方画线。

## 结束事务

主操作点击一次即可执行，不再加一个仅复述按钮文字的确认。动作有明确关闭目标后，Core按以下顺序处理：

1. 冻结本次房间及游戏会话身份，停止接受新连接并使当前邀请不可用，清除可加入状态。
2. 按所选结束方式停止联机，或进一步请求该游戏正常保存并退出。保存由游戏自身执行，启动器不直接改写存档文件。
3. 等待真实游戏终态及网络资源清理，才报告完成。关闭请求已发出、窗口已隐藏或控制接口返回成功，都不等于保存退出已完成。
4. 正常退出受阻时保留游戏，显示当前事实及“返回游戏／重试退出”。不自动升级为强制终止，也不显示一个实际上可撤销不了退出请求的“取消结束”。仅停止网络已经成功时，状态明确反映这一事实。

同一结束事务只能提交一次，重复点击或跨入口重复调用返回同一操作；结束期间的旧连接／开放结果不能把房间改回可加入。退出效果尚未确认时继续核对，不因超时重放未知游戏操作；只有证实失败且目标身份仍相同时才允许再次发起退出。取消开始流程时，复用的已有游戏不因撤销尚未完成的联机而被关闭；本次新启动的游戏必须承接取消及迟到进程结果。

绑定至少包括房间ID、游戏Session、进程启动身份及已观察的世界生命周期。换存档、重新启动游戏或迟到的异步结果，不得关闭另一场游戏或重新开放一个新世界。同一存档中的维度切换不算更换世界。

已有Core可请求经过进程身份核验的游戏窗口正常关闭，但发送请求不证明游戏已退出；当前游戏桥没有保存退出世界／游戏的专用契约。实施时应复用并补齐可靠的关闭与终态观察，适配不到的版本保留实际可用的“仅停止联机／返回游戏”路径，不用猜测命令或强杀冒充顺滑退出。

## 断线恢复

- 世界及游戏仍运行：同一房间有限重试，支持恢复时尽量保留原邀请及客人的本机入口。只重建失效网络资源，不重启游戏、不重新准备整合包。
- 自动开放明确拒绝／取消后，显式重试可创建新操作；结果未知时保留原操作继续观察，不重复执行。手动开放的旧协议世界仍按实际进程归属识别端口。
- 客人固定入口同时承接 TCP 与同端口 UDP。备用地址复用 SRV 解析，区分网络可达与游戏状态可读；状态查询缺失不作登录门槛，后台探测失败不撤销已有游戏流。被动目标更新只影响新会话，已有 TCP／UDP 会话保持原目标；显式停止或更换备用地址仍撤销旧连接。首帧还原原域名、目标端口并保留模组后缀，之后不解释游戏流，不强杀游戏进程。
- 已有发现超时、组件退出、房主失联及协议错误显示具名恢复说明，未知错误保留原错误码和记录导出路径。游戏启动或已有游戏处理错误不因网络刷新成功而消失；网络可连接但游戏状态未知时，明确由游戏确认实际加入结果。
- 网络 bootstrap 在创建时原子归入房间 owner 持有的 Windows Job，owner 异常死亡也撤销其 detached 网络后代；游戏进程不加入这个 Job。
- 自动恢复有明确边界，当前保留每次发现60秒截止和最多3次自动恢复。真实公开发现／组件替换曾需要超过30秒，不能为压到30秒而把仍可恢复的房间提前判为结束；更紧的总体时间预算留待有测量支持的优化。超出次数仍失败时原位提供重试、必要时更换码或使用房主提供的备用地址，不用假进度或无限循环。
- 只有一次桥超时或暂时观察不到世界时，不直接判定房主退出；结合已核验进程、游戏端口和世界事件，区分“失去观察”与“确定世界结束”。
- 只有明确证据时才告诉客人“房主已结束”。不能区分远端主动结束与网络故障时，显示“连接中断”，按恢复流程处理。
- 世界已结束：本次房间进入终态，不自动在另一存档、另一个游戏进程或重新启动后的世界继续托管。再次联机使用新的明确创建动作。

## 页面与迷你窗

沿用当前房间工作区：左侧世界和成员，右侧邀请与环境；实际启动／返回游戏始终可见。状态只在既有状态位置表达，成功后不额外堆“已保存／保留实例”等说明。

房间标题右侧是房主“结束并退出游戏”或客人“离开并退出游戏”；低频仅停止联机放在更多菜单，不并排增加三个同等强调的按钮。结束按钮、footer及文字操作都使用自然高度。

迷你窗沿用320×64及现有材质。只在活动房主、设置允许、主窗最小化／托盘时显示；关闭仅收起本次小窗，返回房间恢复主窗，人数Flyout继续显示真实联机成员。世界结束、房间清理完成后自动消失，不留下一个显示世界已关闭的常驻小窗。主窗关闭仍按既有窗口偏好处理，不把窗口销毁当作停止Core业务的触发器；真正退出App时须通过同一联机清理路径，不遗留失去控制的房间。

陶瓦成员只证实网络参与者，不能直接改称“已入服玩家”。取得可靠游戏数据后才补充游戏内状态；没有资料不生成猜测的头像、玩家数或状态说明。

## 实施顺序与验收

| 优先级 | 交付切片 | 关键完成证据 |
| --- | --- | --- |
| P0 | Core统一结束方式及世界／游戏绑定；CLI可操作；退出世界真正结束房间；同世界网络恢复与结束分离 | 游戏实际退出后房间终态、无残留网络入口；暂时掉线不重启游戏；错误目标及迟到请求被拒绝 |
| P0 | 正常保存退出及失败恢复；房主／客人主动结束语义明确 | 用隔离存档做实际保存、正常退出、受阻重试；不能只凭关闭信号或mock收据通过 |
| P1 | 原生接入结束事务、准确状态及迷你窗终态；加入并启动自动串联 | 正常MSIX及精确PID/UIA实测；Popup取消、已运行游戏复用、房主结束对客人的处理 |
| P1 | 创建时选存档、直接进入、记住有效选择及新世界原生流程 | 正常／空存档／多游戏会话及不同支持版本实测，无法直达时流程仍可完成 |
| P2 | 真正游戏内玩家状态、更多恢复质量信息 | 仅可靠数据支持的增强，不影响标准互通或基础生命周期 |

必须覆盖：正常创建与加入、未进世界取消、游戏启动失败、主动正常结束、退出世界、关闭游戏、换维度、换存档、同世界断网、网络组件崩溃、保存／退出受阻、多游戏与PID复用、旧世界迟到结果、准备Popup关闭、外部客户端互通，以及主窗／迷你窗显示与业务状态分离。

正式回归按[test/GUIDELINES](../test/GUIDELINES.md)先由实施者审查价值与判别力；真实游戏与跨客户端行为单独验证，不用合成状态或通过数量代替。沿用Core → CLI真实验证 → 原生UI的实施顺序，不要求玩家参与常规确认或测试。
