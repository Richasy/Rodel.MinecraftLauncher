# Rodel game bridge agent

Optional Java 17 agent embedded by Core; independent of Rodel UI and mod loaders. No third-party Java dependency. One narrow transformer wraps the exact native KeyMapping getter, retaining straight-line instance boolean return-value modifiers such as Xaero's. It validates the boolean field, `(Z)Z` calls and typed one-word stack, including MixinExtras' `ALOAD_0/SWAP` receiver placement. Branches, exception handlers, local-variable changes and other shapes still leave the class unchanged and refuse input; unsupported exact-getter opcodes are reported without game state. Production source is in `src`, with the JDK-only bootstrap helper in `bootstrap`, manifest in `agent.mf`; `scripts/build-game-bridge.ps1` creates the deterministic JAR in Core obj and embeds it. Do not commit generated binaries.

A build requires JDK 17+ (`GameBridgeJavaHome`, compatible JAVA_HOME or PATH); end users need only the game runtime. Core generates exact bindings from SHA1-verified official client mappings or explicit 26.3 names. Fabric remapping uses the loader public resolver after actual main definition; game access waits for client initialization evidence.

The owning Core monitor passes ephemeral configuration through reserved environment variables. The agent authenticates using mutual HMAC challenges and exchanges bounded length-prefixed JSON-RPC on loopback. Never print the secret, add an external listener, preload game classes or mutate game state on an IPC thread. Reads run on the client executor; only an owned integrated server with a memory connection permits typed edits, native controls and container actions. Commands additionally require actual cheats and original player permissions. Every native key read rechecks world/player/server/connection identity; physical keys remain untouched. Native serialization exposes bounded SNBT, not arbitrary Java evaluation. Remote servers always remain read-only.
