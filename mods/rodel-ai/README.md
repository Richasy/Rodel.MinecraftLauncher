# Rodel AI

由启动器随包提供，在“内容 → 模组 → 内置模组”勾选Rodel AI并点击“安装所选”。按实际游戏及加载器选择精确包和依赖，不使用社区分发。Fabric/Quilt 需要匹配 Fabric API；Forge/NeoForge 使用原生包。所有目标均不依赖 Rodel UI。

客户端目标包括**26.3 / Fabric、Quilt、Forge、NeoForge / Java25**，既有Fabric26.2、26.1.2，以及**1.20.1 / Forge / Java17**。发布版本统一为0.0.1，具体范围见[兼容矩阵](../COMPATIBILITY.md)。默认模型、上下文、持久历史、工具与许可复用C# Core；Java只负责命令、消息和渲染，不保存密钥或另建模型循环。

## 安装与入口

启动器按实际目标安装所需依赖，不混装不同游戏/加载器或sources JAR。在实例中启用游戏桥，并通过启动器重启游戏；启动器AI设置须有默认模型。无桥时模组仍可加载，入口明确说明连接或配置缺失。

- `/rai 消息`：在当前存档的同一个会话里连续提问，可以追问前面的回答；与侧边面板共用上下文。问题和“正在回应”先进入本地聊天历史，终态后显示完整回答，不把文本增量刷到聊天栏。提交后保留原生聊天框，输入清空以便追问，Esc仍能关闭；状态更新刷新自身显示时间，普通聊天及服务器消息不变。
- `/rai_new`：开始当前存档的新会话，与侧栏“新会话”使用同一清理流程，不删除游戏存档。
- 暂停菜单的“AI 助手”（或不带参数的 `/rai`）：打开右侧聊天面板，并使用Minecraft原生暂停，自有未公开的单人世界会停止模拟。关闭后返回真实父页，原父页仍暂停时继续暂停。多人及已公开LAN世界无法由客户端暂停，页头会明确提示；不会伪造暂停或改成无敌。沿用真实游戏画面、自己的主题与 Minecraft 原生字体／GUI 缩放，保留原生多行编辑器、输入法、焦点与旁白。支持连续对话、流式纯文本、停止、较早消息、问答选择及精确操作许可。
- 输入框按内容在两至四行内增高，更多内容内部滚动；Enter发送，Shift+Enter换行。提问与回答采用不同阅读层级；向上阅读后可“回到最新消息”。生成中发送按钮的位置显示停止，问答和审批按各自真实状态显示操作。回答区不提供复制按钮。
- “新会话”只清除当前存档上一段 AI 对话，停止该对话未完成的回合；不清理玩家游戏存档，也不影响其他存档的 AI 历史。

对话屏使用 `AiTranscriptLayout` 保留当前一份文字排版，未变化的绘制帧不重新测量整段历史。Core响应提交、可用宽度、密度、主题、审批详情及原生语言资源变化会重新排版；滚动和原生选项按钮位置仍实时更新。初始化和离开页面会释放旧排版，不缓存输入控件或另存会话。

侧栏出现问题后，点击任意选项即提交该选项，无需再点回复；自由输入仍用发送或Enter提交。点击选项保留尚未发送的文字草稿。等待问题时发送的普通新消息由Core直接归入该问题并记录为已回复，不创建排队回合；重复传送同一提交只返回原回执。控制台来源不提供ask_user，模型需要补充信息时直接用纯文本询问，玩家下一条`/rai 消息`继续会话；也可用控制台消息回答同存档侧栏已有的问题。

Forge1.20.1使用原生全页记录和单行EditBox，复用同一控制器；支持连续会话、选项点击直接回复、自由文字回答、停止/重试和可滚动的确认详情。滚轮或PageUp/PageDown阅读记录，零滚动跟随最新消息。现代版的多行输入和现代侧栏布局不套到旧版。实际配方、FTB任务/团队进度与Patchouli手册由Core游戏桥查询，不在模组内实现包专用玩法。

## 历史与范围

游戏对话只属于本次游戏进程。Core在启动器数据根的`ai/game-slots/<sessionId>`内按**实例＋本地存档目录**暂存会话引用，同一进程内重进存档时控制台与面板可复用；关闭游戏清理全部所属对话、事件及问答和槽引用，后续启动从空会话开始。游戏对话不进入启动器AI历史；启动器自己的会话独立持久保存。异常遗留按记录的Java进程ID及启动时间核对清理，不凭标题或实例名删除历史。服务器连接以实例＋服务器地址分槽，不声称能区分服务器未同步给客户端的多个世界。连续提交时各控制台观察者按原始提交身份取得自己的最终回答，不把后一个排队问题的状态误当成前一个回答。

新消息使用启动器当前默认模型；游戏入口由Core复用既有`AllowOperations`授予本回合操作许可，不再逐条授权游戏指令，不更改启动器普通对话或全局默认模式。原生作弊、玩家权限、实例/会话/世界绑定与未知效果守卫仍生效；精确文件范围等独立确认继续复用Core。游戏内来源会在 C# 系统提示中加入“纯文本、不使用 Markdown”的要求；启动器内普通聊天仍保留既有 Markdown。模型仍可能不遵守格式指令，游戏按纯文本呈现，不解释 Markdown 或模型生成的可点击命令。

游戏回合绑定真实 session、Java incarnation 和提交时的世界。仅自有本地内置服务器可修改；命令另需原生作弊及玩家权限。多人、独立服务端、LAN 访客、Realms 包括 OP 仍只读。世界切换、断连与失败不会自动重发模型提交或游戏操作；失去响应后使用原提交身份观察/重试，不生成新身份冒充恢复。

## 构建

模组使用独立的256×256像素对话图标，由Azure ImageGen生成；`assets/rodel_ai/icon.png`供Fabric元数据引用，启动器内置模组选择器随包携带同一图像，不依赖网络或开发目录。

使用 JDK 25，在本目录运行：

```powershell
.\gradlew.bat build
```

Rodel AI 独立编译和运行，不引用或要求 Rodel UI，也不借用它的字体、主题或绘制 API。JAR 不打包 Minecraft、Fabric 或模型 SDK。正常运行不依赖源码目录或开发机器路径。桥 agent 由正常启动器构建嵌入，保持 Java 17 字节码与既有游戏适配能力。

受控模型/Java 夹具、构建、NativeAOT 和实际游戏界面分别验收，不相互替代；已登记的游戏与加载器组合见[兼容矩阵](../COMPATIBILITY.md)。

已在独立26.3/Fabric实例使用真实默认模型验证两种入口、A/B存档隔离、新会话清理、后台读取时发送排队，以及批准后实际发放64钻石并读回/重启确认。1280×720下GUI倍率2和3的侧栏与审批截图已检查；输入法组合提交和完整键盘导航仍未实测。正常玩家实例与存档未改。

## 模组主题设置

从模组列表配置或 AI 侧栏的设置按钮进入，浅／深色只影响 Rodel AI。完成时保存到 `config/rodel-ai-client.properties`，取消不改动。Fabric／Quilt 的列表配置使用可选 Mod Menu，Forge／NeoForge 使用原生配置工厂；默认浅色，不读取启动器或其它模组的主题。输入和 IME 使用 Minecraft 原生坐标与字体。
