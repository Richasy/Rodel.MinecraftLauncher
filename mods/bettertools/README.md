# Better Tools

独立的工具魔方模组，不依赖启动器、Rodel UI 或 Rodel AI。支持 26.3 Fabric／Quilt／Forge／NeoForge，26.2／26.1.2 Fabric（Java25），以及 1.21.11 Fabric（Java21）。精确加载器版本和其他内置模组的不同验收范围见[兼容矩阵](../COMPATIBILITY.md)。

## 使用

- 铁锭四角、铜锭四边、木棍居中合成工具魔方；无铜的早期目标以光滑石头替代铜。当前已支持目标均含铜，不增加未验证旧版的兼容声明。
- 对空保留上一次可用工具；看向方块立即切换工具，准心对准 32 格内无遮挡生物即切换武器，实际攻击距离仍遵循原版。
- 在原有物品栏或容器中悬停魔方即可查看两行十格浮层，不打开新界面、不复制玩家背包。每行依次为镐、斧、铲、剑、锄；第一行主用，第二行备用。
- 右键原版允许耕作的土壤时优先切换锄子并执行原装备的真实耕地动作；原生土壤／朝向／上方空间校验和耐久消耗保留。没有锄子时仍由现有原装备处理右键；战斗保持期间不为耕地切走武器。
- 与收纳袋一样，光标拿着装备点击魔方即可收纳，优先对应主用格，再进入备用格；满列或类型不符保持原样，不交换整个魔方。
- 悬停魔方时滚轮仅在已有装备间循环，选中格高亮并显示装备名；空光标右键魔方将所选原装备取到光标，然后按原版方式放入背包。
- 滚轮选中工具后按 Tab，交换该类别的主用／备用位置，黄框跟随同一件原装备；另一格为空也可移动。再次按 Tab 换回，原装备的附魔、组件与独立耐久保留。
- 左键可拿起整个魔方；光标拿着魔方点击已有装备可收纳，右键空物品格可取出一件装备到该格。拒收的目标格保留完整原状态。光标及关闭物品栏沿用原版处理。
- 优先能正确采收的同类主用，其次同类备用；主用能完成工作时，不因为备用更高级而抢用备用。损坏先由同类备用接替，耗尽该类则选其它可用装备。战斗按剑、斧、镐、铲、锄依次回退，各类先主用后备用。
- 库存／快捷栏使用当前原装备的图标，加小魔方角标；耐久条直接采用该装备的原生计算。空闲或编辑时记住最后使用的装备，移除它后清除显示，不修改魔方外壳的伤害组件。持有时保留真实工具；整理物品栏、切走快捷栏、丢出或死亡时才收回魔方。
- 空格由当前资源包中原版铁制工具贴图的透明边界提取空心轮廓，沿原版纹理形状描边；原生资源重载自动更新。紧凑浮层使用暖白／深灰两套配色，标题带线框魔方与信息图标，两行十格使用黄框选中；上方显示所选原装备的名称、真实耐久与主备位置，底部鼠标图标和 Tab 键帽说明操作。主题由自身设置保存，不借用 Rodel UI；Minecraft 原生位图文字按原生 GUI 像素绘制，不做分数缩小。
- 方块优先其原生工具类别，再选择现有工具中实际有效且速度大于徒手的工具；无法正确采收的工具不会冒充有效工具。没有有效工具时保留当前可用工具，再回退最近使用或其它现存工具；只有没有可用装备才显示魔方。回退不改变原版采收／掉落条件。

受到实体攻击立即准备武器；挥剑即进入战斗保持，挥空也计入，每次挥砍或受击刷新五秒（100 游戏 tick）。目标死亡或五秒没有继续攻击／受击后重新按准心选工具；仍瞄准生物则继续持武器。保持期间扫到方块不切走武器；没有剑使用战斗回退。变形立即更新可见原装备，不等待收起／拿出动画，也不额外清空已有攻击蓄力；正常攻击冷却保留。

旧版八格魔方随玩家物品组件读取扩展为十格，原有主备装备、活动／显示／滚轮选择和魔方外壳一起映射，附魔与耐久不变。

变形时真正拿出玩家放入的原装备，完整保存其数据组件、附魔、自定义属性和独立耐久。使用中消耗的是当前原装备；损坏只删除该装备。库存编辑暂停自动切换，丢出物品或死亡掉落时恢复魔方外观并保存剩余装备。多人服务器和客户端都需要安装。

死亡前会先将活动装备收回魔方，按容器掉落；内部装备保留消失诅咒等附魔数据，但单件活动装备的诅咒不会删除整个魔方及其他装备。

## 更新已有实例

先更新启动器，再保存并正常退出Minecraft。在内容页选择原实例，打开“模组 → 内置模组”，重新勾选Better Tools并安装，完成后重启游戏。内置包的实际内容不同就可以更新，不要求显示版本号发生变化；更新启动器不会自动替换已有实例里的JAR。多人客户端与服务器需要匹配的更新包。

旧八格魔方随新版本读取保留原装备并扩展为十格，玩家无需取出重装。玩家操作说明与实机配图见[中文指南](../../website/content/docs/mods/bettertools.mdx)及[英文指南](../../website/content/en/docs/mods/bettertools.mdx)。

## 构建和验证

使用 JDK 25，在本模块运行 `./gradlew build runClientGameTest --no-daemon`。客户端游戏测试创建模块 `build/run/clientGameTest` 中的隔离世界，不打开玩家存档；测试源码不进入发布 JAR。

用 `-Pminecraft_target=26.2`、`26.1.2` 或 `1.21.11` 选择旧目标；最后一个客户端任务通过 Gradle toolchain 使用真实 Java21，编译仍可用 JDK25。`gradle/legacy-target.gradle` 只承接已核对的 API 名称和原生界面生命周期差异。

`nativeTestJar` 生成独立 Fabric／Quilt 实例验收包，`../loader-build/{forge,neoforge}` 的 `bettertoolsTestJar` 生成对应原生验收包。它们使用 `src/gamecheck` 的共同原装备不变量和 `src/nativetest` 的客户端／服务端协议检查。只在新建隔离世界加载产品 JAR 加独立测试 JAR，向 JVM 提供 `-Dbettertools.test.result=<隔离结果文件>`；实际库存交互、目标切换和死亡掉落完成后写入终态并正常关闭。测试包会修改该隔离玩家的库存并执行死亡边界，不在玩家存档使用，不随 CLI／App 分发。

构建与客户端通过之外，Core 的 `BundledModTests` 以实际产品 JAR 验证七个目标的单独选择、匹配 API、冻结安装、禁用／启用及重复安装；不把这些安装检查称为游戏运行证明。启动器内置目录沿用 `content bundled`／`review-bundled`／`apply-review`，App 沿用既有选择器。

测试设计审查：现有回归延续保护真实容器点击的物品守恒、完整组件持久化与原生损坏接替、服务端目标判断和同步界面。判别依据是原物品的完整组件快照、独立预期物品数量和实际手持物品；不复写产品选择器当作预期值，也不以界面构造成功代替服务端点击结果。

显示回归复用原装备／损坏流程，检查主用与备用具有不同耐久时的原生条宽、颜色和完整物品组件；客户端截图另核对图标角标及原物品栏内的悬浮预览，不以纯数值断言代替实际绘制。

魔方面纹理由 Azure `gpt-image-2.5-flare` 原创生成，再缩至 32×32；三维立方体由原生模型提供；工具格轮廓在资源重载时从原版／资源包贴图派生，不随模组复制原版贴图，不依赖在线图像服务。

本次交互回归审查：扩展既有真实库存流程，要求原 InventoryScreen／menu 保持不变、滚轮选择经真实网络到达服务端、右键取得选中备用而非主用、手持魔方能取放工具、拒收格不丢失装备。完整原件快照和实际槽位／光标状态可区分新旧交互及丢失、复制；不新增仅验证类名或文案的用例。

Tab 回归复用该流程，经过真实键盘回调与服务端通道，比较交换前后完整原件、选中位置及记忆图标；空格移动归共享存储检查。过期菜单／魔方身份／选中请求必须保持原状态。浅／深色截图通过真实模组设置切换、保存并返回同一个物品栏；Native JAR 验收分别覆盖加载器的独立通道注册。

耐久恢复挂接所有实体／手持重载最终共用的服务端扣耐久入口，也处理直接调用该入口的路径；只恢复实际手持的原装备，不从脱离背包的副本生成魔方。剑损坏后的原版战斗收尾必须识别已经接替的同一魔方，不能误清空副手。

回归使用隔离真实世界：`BetterToolsGameTest`覆盖十格网络取放与保存重进，`CombatGameTest`覆盖视线、原生伤害／冷却、挥空续时、结束包顺序和主备剑损坏后的副手守恒，`FarmingGameTest`执行真实右键耕地及主备耐久接替，`MiningGameTest`通过真实客户端持续砍树／挖矿耗尽主备铁斧／铁镐并核对其余八件完整原装备。旧八格独立夹具、满十格连续损坏至空壳和完整组件比较归共用`CubeStorageChecks`；直接服务端扣耐久与原生挖矿分别覆盖。右键返回结果必须保留原生损坏钩子已经装上的备用装备，不能被已消耗的工具覆盖。

## 主题设置

通过模组列表的配置动作或客户端命令 `/bettertools config` 选择浅／深色，完成后保存到 `config/bettertools-client.properties`，取消保留原选择。Fabric／Quilt 的列表入口使用可选 Mod Menu，Forge／NeoForge 使用原生模组列表。配色、面板和字体不读取或反射 Rodel UI，也不跟随启动器主题。
