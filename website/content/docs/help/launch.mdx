---
title: 游戏无法启动或进入
description: 先辨认卡在哪个阶段，再保留证据、逐项恢复。
---

## 先做三件事

1. 保留屏幕上的完整错误、实例名称、游戏版本和刚改过的内容。
2. 重要世界先备份，不要先删实例或清空数据目录。
3. 查看当前任务与游戏窗口，确认是还在准备、已经启动，还是确实失败。

| 卡住的位置     | 先检查                                     |
| -------------- | ------------------------------------------ |
| 添加或验证账户 | 账户是否有效，是否为应用注册或服务访问错误 |
| 下载文件       | 来源、网络、磁盘空间与任务中具体失败文件   |
| 选择 Java      | 实例要求与当前指定运行时                   |
| 模组加载       | 版本、加载器、必要依赖与最近变更           |
| 打开世界       | 世界版本、模组缺失与文件占用               |
| 加入服务器     | 地址、身份、客户端匹配和服务器提示         |

## 下载中断

先检查任务中的具体来源。网络恢复后重试，已有文件会按实际条件复用或尝试续传；上游不支持续传或校验不一致时可能重新下载。

若只有某个平台不可用，仍可管理本地内容。不要把整个实例删掉来重试一个文件。

## Java 或内存错误

先看是否有实例专门指定的 Java，再看全局默认。旧游戏和新游戏可能需要不同运行时，使用实例运行环境入口或[Java 管理](/docs/create/settings#java-与内存)处理。

内存分配失败时，关闭不需要的程序，检查手工最大内存与高级参数是否冲突。不要把电脑全部内存都给游戏。

## 新加模组后失败

核对游戏版本、加载器和缺失依赖。先停用最近添加、且有证据相关的内容，每次只改一组清楚的因素。

不要随意移除世界依赖的模组后直接保存唯一存档。需要尝试时用副本，保留原环境。具体内容操作见[模组安装](/docs/play/content)。

## 窗口出现了却还没进游戏

游戏第一次加载、模组初始化或资源重载可能继续进行。观察游戏状态和任务，不要因为进程已经创建就重复点击启动。

长期无响应时保留日志。能正常关闭就先正常关闭；强制结束可能打断保存，只在确认情况后使用相关操作。

## 世界被占用或版本不匹配

确认同一世界没有在另一份游戏中打开。不要删除锁文件绕过仍在使用的存档。

更高版本或缺少模组的世界可能不能按旧环境加载。先保留原件，回匹配环境或从备份恢复，见[世界管理](/docs/play/worlds)。

## 服务器加入失败

启动器显示“游戏已启动”并不等于入服成功。以游戏实际断开提示为准，检查账户、地址、版本、白名单或服主要求。见[服务器指南](/docs/play/servers)。

## 房间连上了，游戏进不去

先看 Minecraft 的实际断开提示。房间连接就绪只解决网络入口，游戏版本、加载器、模组和身份仍由 Minecraft 检查。只有房间码时向房主确认环境，有共享包时先完成包准备。

如果房间本身显示断开，保留游戏并在联机页重试，恢复后重新连接。房主退出或更换世界会结束原房间，此时需要新的邀请。详细操作见[联机指南](/docs/play/multiplayer)。

## 请 AI 分析

错误详情有 **“AI 分析并修复”** 时，可以使用已配置模型继续。它会围绕这个实例和故障记录寻找依据、准备受限修复，并观察新的运行。

初始化检查通过后，仍需回到原场景确认；不合适时查看撤销入口。详见[AI 故障处理](/docs/create/assistant#用-ai-分析一次启动故障)。

## 仍不能解决

按[反馈与日志](/docs/help/feedback)提供复现步骤、完整错误和必要日志，隐藏账户凭据及私人地址。说清是哪个阶段失败，比只写“打不开”更容易定位。
