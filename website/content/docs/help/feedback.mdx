## 去哪里反馈

欢迎优先到 [GitHub Issues](https://github.com/Richasy/Rodel.MinecraftLauncher/issues) 提交问题或建议。提交前搜索一下是否已有相同问题；已有讨论时补充自己的复现条件，方便一起跟踪处理结果。

GitHub issue 通常公开可见，请只附排查所需的信息。

## 一个有帮助的反馈

可以按下面填写：

> 我想做什么：导入一个已有实例。
>
> 我做了什么：选目录后开始复制。
>
> 实际发生什么：复制到某文件时任务失败。
>
> 我原本期望：复制完成，并出现新实例。
>
> 环境：Windows 版本、x64 或 ARM64、启动器版本、游戏版本与加载器。
>
> 是否每次出现：重新尝试后的结果。
>
> 最近变更：新模组、Java、代理或目录变化。

说明已经尝试的操作，避免别人建议你重复处理。若问题只影响一个实例，也请写明。

## 先确认版本和错误

在 **设置 → 关于此应用** 查看并复制启动器版本。错误弹窗或任务详情中能复制的完整错误，也请一起保留；截图可以说明界面位置，但不要只截报错的最后一行。

## 按问题选择日志

打开 **设置 → 日志与诊断**，启动器和游戏有各自独立的导出入口：

| 问题发生在哪里                     | 使用哪个入口 | 需要选择什么                                          |
| ---------------------------------- | ------------ | ----------------------------------------------------- |
| 启动器界面、账户、下载、导入或任务 | 启动器日志   | ZIP 保存位置；不需要先启动游戏                        |
| 某次游戏启动、运行或崩溃           | 游戏日志     | 实例、对应启动时间的运行记录、导出内容和 ZIP 保存位置 |

**启动器日志** 汇总最近七天的软件运行记录，并尝试隐藏常见凭据。**游戏日志** 中，诊断包会汇总可用的诊断信息并尽力脱敏；原始日志保留原始字节，适合需要核对编码或完整输出的情况。两种导出都要在分享前自行检查。

按问题发生的时间选择游戏记录，不要把一次正常启动的日志当作另一回崩溃的证据。运行中的游戏输出只保留有界的内存窗口；正常退出不会另外保存一整份控制台记录，异常退出可能留下崩溃快照。游戏自身的日志、已有崩溃报告与启动器日志是不同来源。

选择保存位置并导出后，检查结果与缺失来源提示。没有记录或部分来源不可读时，先提供错误原文、发生时间和已导出的有效部分，不必为了凑齐日志重新安装或删除实例，也不要默认上传整个数据目录。

日志中文字乱码时，保留原文件，注明所用游戏版本；不要用反复转换后丢失内容的文本替代原件。

## 截图时隐藏什么

检查是否露出：

- 微软、外置账户或 AI 服务密钥、令牌和设备登录码。
- 私人服务器地址、聊天内容和未打算公开的世界信息。
- 本机用户名、完整个人路径和其他窗口内容。

> [!WARNING]
> 分享前先裁切或遮挡私人内容。**不要发送密钥、令牌、微软密码或设备登录码。** 邮件附件也只提供排查需要的片段，不要打包整个数据目录。

## 联机与地图问题

联机问题说明自己是房主还是加入者、卡在哪个状态、双方游戏版本和模组。联机页的 **导出连接记录** 用于排查房间连接；已经进入 Minecraft 后被踢出时，同时保留游戏的断开提示。邀请码不要放进反馈正文。

地图问题说明是输入种子还是实例世界、版本、维度、视图和坐标。筛种问题补充条件、参照位置、采样间隔与预算。只需展示地图或条件时，不用附整个存档。

## AI 和皮肤问题额外提供什么

AI 问题说明服务类型、模型标识、操作模式和失败发生在哪一步，不附 API 密钥。只分享与问题有关的对话与工具过程。

皮肤问题说明是人物还是披风、纹理尺寸、当前图层和复现步骤。搭配预览问题同时说明正在编辑哪件作品；PNG 导入问题给出图片宽高。要提供工程或参考图前，确认你愿意公开其中内容；导出 PNG 和完整工程包含的信息不同。

截图管理问题请说明所选实例、图片文件名、使用的是打开、重命名、导出还是删除，以及是否选择了直接删除。图片或目标文件发生变化时，保留错误提示，不要反复覆盖文件。操作入口见[截图管理](/docs/play/screenshots)。

## 提建议也可以很简单

描述玩家场景和你遇到的阻碍，例如“第一次装模组时，不知道应该选哪个实例”。如果有改进想法可以一起写，但不需要先提出技术方案。
