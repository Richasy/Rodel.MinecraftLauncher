## 它能帮我做什么

AI 是 RMCL 的主要探索方向之一：帮助新手理解版本、加载器、模组依赖和启动提示，也可以在许可范围内读取实例信息、查找内容、处理任务或协助皮肤设计。

你仍可以不配置 AI，直接使用启动器的基础功能。AI 不是内置玩法托管，也不会自动替你游玩或保证修复每个问题。

## 1. 添加一个模型服务

打开 **“设置 → AI”** 的模型服务区域，选择 **“添加服务”**。

1. 选择自己使用的服务类型：OpenAI 兼容服务、Anthropic 兼容服务或 Gemini。
2. 在线服务按提供者说明填写服务地址与 API 密钥。使用该服务的凭据，不是微软账户密码。
3. 读取模型列表，勾选想保留的模型；服务不返回列表时，也可以填写实际模型标识。
4. 保存后回到 AI 助手，选择刚添加的模型。

模型服务可能单独计费，使用前查看提供者说明。网页聊天订阅是否包含 API 使用取决于提供者，不能仅凭自己能打开其聊天网站就判断。

当前发行版仅提供在线模型服务，暂不提供本地 GGUF 模型的添加和使用入口。已有本地配置会保留，不会自动改用在线模型。

如果准备主要在游戏里使用，记得把可用的在线模型设为默认模型。步骤见[游戏内 AI](/docs/create/game-ai)。

## 2. 从一个小问题开始

选择 **“新对话”**，确认模型与实例上下文。实例选择决定下一轮围绕哪套游戏讨论。

可以这样提问：

> 我第一次装模组。请先看看“林地生存”的游戏版本和加载器，解释我还需要准备什么，暂时不要修改文件。

> 这个实例启动失败。请根据本次日志说明最可能的问题，把已确认的原因和还需要核实的部分分开。

> 我想给这个实例加一个整理背包的模组。先找合适候选，告诉我版本和依赖，再由我决定。

想问生存常识也可以直接描述场景。回答来自你选择的模型，遇到重要操作仍要看实际来源、游戏提示和执行结果。

## 3. 理解操作权限

普通聊天可以解释问题；需要实际工具时，权限与访问范围决定能做什么。

> [!TIP]
> 普通新对话默认使用 **“安全”** 模式，写入操作会先申请批准。可以在 **“设置 → AI → 对话默认值”** 中调整；已有对话保留自己的模式，先确认输入区当前显示的选择。

## 文件和网络开关

文件能力只在已授权范围内访问。当前数据目录与应用包数据目录有固定范围；需要其他文件夹时，在设置里明确选择，并区分只读与可读写。

> [!WARNING]
> 选中目录不会自动上传全部内容，但任务实际读取的相关内容可能随请求发给所选在线模型。只开放当前任务需要的目录，不要为了读一份日志而开放整块磁盘。

网络能力用于检索或读取网页；关闭它不等于关闭在线模型连接。服务不可用、搜索无结果或页面拒绝读取时，助手应保留这些限制，不能把猜测当成查询结果。

## 需要你回答时

助手可能提出选择题、要求补充信息或等待目录授权。按请求回答后继续当前目标，不必重复发起同一条操作。

自由回答框为单行，按 **Enter** 或点击提交都可以发送。填写前先看当前问题；输入法候选尚未确认时，先完成选字。

## 响应中追加消息

可以边等边补充条件，例如“只找 Fabric 版本，先不要安装”。新消息进入排队后，在当前工具批次返回、下一次请求模型之前按顺序接入，不必等到整段长任务结束。

| 操作               | 什么时候用                         |
| ------------------ | ---------------------------------- |
| 普通发送，进入排队 | 补充目标，让当前已开始的工具先返回 |
| 取消排队项         | 这条补充不再需要，当前响应继续     |
| 立即发送           | 停止当前响应，把这条消息提到下一项 |
| 停止               | 不再继续当前响应                   |

助手正在等你回答或批准时，先处理那个请求；排队消息不会替你作答。每项保留提交时的实例、模型、参考图和权限选择。

历史列表区分响应中、待回复、排队和未读。向上阅读会暂停自动追底，发送新消息或立即发送会恢复追随；切回历史可以继续读已经完成的回答。

切到其他页面不会自动停止对话。想停止当前响应，使用 **“停止”**。已经派发的独立下载任务可能继续，必要时还要到原任务查看或取消。

## 长对话与上下文

对话接近模型上下文预算时，启动器可以自动整理较早的内容，保留本地原始归档，并为模型选择需要的原文片段。原始聊天不会因此删除，已经完成的操作也不会因整理上下文而重新执行。

看到上下文整理阶段时，等待它结束即可继续。更换服务或调大上下文前，先确认模型支持的容量和本机资源；长篇整合包排查也可以另开一段对话，把当前目标和已确认结果带过去。

## 用 AI 分析一次启动故障

在错误详情中选择 **“AI 分析并修复”**，会沿用当前 AI 能力，把目标固定到相关实例和故障记录。没有可用模型时，先选择模型再继续。

它会根据证据准备范围有限、可回退的处理，例如调整有依据的 Java 或内存、停用一个确定相关的模组，或补充能够准确识别的依赖。证据不足时会询问，超出范围的变更不能只靠一句“全都允许”扩大。

查看方案、实际修改与新运行观察。**“启动初始化检查通过”不等于已经验证你在游戏内遇到的所有问题**。仍需回到实际场景检查；不合适时使用这次修复的撤销入口。

## 回答中断或结果不确定

> [!CAUTION]
> 回答中断不代表操作没有执行。**先检查任务、文件或实例状态，再决定是否重试。** 已提交的修改可能保留，重复安装、写入或删除可能产生第二次变更。

启动器会自动核验操作结果。如果仍出现无法确认的警告，先核对实例、文件或任务状态，再决定下一步；警告不表示一定没有改动，不要直接重复同一修改。

对话与已提交消息会保留，可以返回历史继续。反馈 AI 问题时，提供服务类型、错误与必要过程，删除密钥和私人上下文。

## 可选的游戏数据桥

**“游戏数据桥”默认开启**，让助手可以参考受支持的当前游戏，而不只读启动日志。以前明确关闭的全局或实例设置仍保留；需要时在游戏启动设置或实例的同名入口重新启用，也可以主动关闭。改动只影响下次启动，已运行的游戏不会被中途接入。

进入受支持的世界后，它可以提供位置、生命和有限的世界、背包等信息。本地单人世界还提供范围有限的原生操作；与其他服务器连接时始终只读，包括同一台电脑上的独立服务器。允许操作模式不会改变这条边界。

想直接在游戏内追问，安装 Rodel AI，然后从暂停菜单或 `/rai 消息` 进入。它可以结合适配整合包的配方、FTB 任务／团队进度和 Patchouli 手册回答问题；具体操作见[游戏内 AI](/docs/create/game-ai)。

主菜单中的“等待进入世界”表示尚无世界上下文。游戏内对话只保留本次游戏进程，退出游戏后清理；启动器这里的会话则单独持久保存。

## 与皮肤设计器、外部工具的关系

皮肤设计器的 AI 共用模型，但编辑范围仅限当前皮肤；详见[皮肤设计器](/docs/create/skins)。

已经使用 Codex 或 Claude Code 的玩家，还可以在设置的外部 AI 工具中预览并安装启动器接入。先核对目标与安装计划，这不是新手完成基础游戏准备的必需步骤。

对话、文件与模型服务的数据去向见[隐私说明](/docs/project/privacy)。
