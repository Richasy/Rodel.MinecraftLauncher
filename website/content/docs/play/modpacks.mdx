## 整合包适合什么情况

整合包把一组模组和配置整理在一起。它可以省去逐个选择的工作，但仍需要匹配的游戏版本、加载器和运行环境。

当前支持 Modrinth **.mrpack** 和 CurseForge **ZIP** 离线导入。普通 ZIP 不一定是整合包；已经完整安装的游戏目录可以走[迁移导入](/docs/play/import)。

## 导入一个包

1. 在实例页打开整合包导入，选择可信来源的包文件。
2. 核对包名、版本、游戏版本和格式。
3. 填写实例名称，确认目标位置。
4. 查看可选内容，决定是否包含客户端可选项。
5. 开始导入，按连续的任务步骤完成内容、加载器和 Java 准备。

可选项目会按包的声明单独列出。开始后，页内进度依次显示导入文件、准备加载器和 Java 等步骤；下载中断时保留已经完成的内容。

## 把包文件拖进来

也可以把 `.mrpack` 或 CurseForge ZIP 拖到首页或实例列表。启动器先打开导入表单，读取包名、版本与所需游戏环境，再由你填写实例名。拖入文件不会立即改动现有实例。

## CurseForge 包需要手动补件时

当前默认不提供 CurseForge 在线搜索和 API 下载，但保留离线包导入、补件、导出和来源信息。

按缺件清单到包作者或项目提供的来源取得对应文件，在对应条目选择本地文件，再点继续准备。选择文件先暂存，继续时按清单校验大小和哈希；选错文件会留在待补件状态，可以重新选择，不用重建实例。

| 任务状态                       | 怎么继续                         |
| ------------------------------ | -------------------------------- |
| 等待手工补件                   | 按条目取得精确文件，选择后继续   |
| 某个下载失败                   | 检查该来源与网络，重试未完成步骤 |
| 内容完成，加载器或 Java 未完成 | 使用实例的继续准备运行环境入口   |
| 已取消准备                     | 保留实例，准备好后显式继续       |

## 内容已导入，环境还没完成

保留已登记实例，使用它的 **“继续准备运行环境”** 入口。下载失败时先查看具体来源与网络提示，再重试未完成步骤，不必再导入第二个实例。

第一次运行先用一个新世界确认基本情况，再放入重要旧存档。

## 已有包怎么更新

更新前备份世界与当前配置，阅读包作者的升级说明。支持检查来源的包可先查看可用更新和文件差异，再确认应用。

服务器分发包还可能包含专门的受管文件。检查中看到玩家修改、额外内容、缺件或冲突时，先了解处理范围；不应把“发现新版”理解成已经覆盖全部文件。

只应用你刚刚核对的清单。更新后的游戏仍需要实际启动检查。

## 回退与停止跟随来源

> [!CAUTION]
> 有可回退记录时，按对应的包历史入口查看最近事务与恢复范围。回退内容更新不等于倒退游戏内已经保存的世界，因此升级前的世界备份仍然必要。

停止来源检查只解除后续跟随，不删除游戏文件。界面入口与可用操作会随包格式和当前状态而变化；不支持的在线来源会明确报告。

## 导出给朋友

从实例管理的菜单选择 **导出整合包**，填写包名、版本、作者和目标文件，再核对导出结果。导出的 Modrinth 包会记录游戏、加载器与可识别内容的来源，接收方可以用同一个导入流程准备实例。

普通导出与[联机页](/docs/play/multiplayer)的 **分享整合包** 范围不同：

| 方式         | 适合的用途             | 分享前核对                     |
| ------------ | ---------------------- | ------------------------------ |
| 实例菜单导出 | 打包这套玩法与配置     | 本地文件、配置及排除项         |
| 联机页分享   | 让朋友准备相同的客户端 | 启用内容的引用、共享配置和脚本 |
| 世界导出     | 分享建筑和游戏进度     | 目标存档、玩家数据及隐私       |

联机分享排除个人游戏选项、服务器收藏、存档及没有来源的本地二进制。导出结果列出排除项或未完成内容时，按清单告诉朋友还缺什么；内置模组由对方自己的 RMCL 安装。

世界需要[单独导出](/docs/play/worlds)，Java 与共享游戏依赖由接收方准备。自定义配置可能包含私人地址或凭据，分享前检查这些文件。
