## 什么时候需要另一个实例

想同时玩原版生存、建筑和模组冒险，可以分别创建实例。每个实例有自己的游戏内容、设置和世界；适合共享的运行资源由启动器复用，不需要手工整理。

不要直接在唯一的生存实例里反复替换大批模组。先创建副本，在副本里尝试会更容易恢复。

## 新建、迁入还是导入包

| 手里有什么                | 使用哪条路线                      |
| ------------------------- | --------------------------------- |
| 想从空白原版开始          | 新建原版实例                      |
| 已有可玩的游戏目录        | [导入已有游戏](/docs/play/import) |
| .mrpack 或 CurseForge ZIP | [导入整合包](/docs/play/modpacks) |
| 只想加几个模组            | [内容管理](/docs/play/content)    |
| 想保留原配置做试验        | 在实例管理中创建副本              |

## 找到并整理实例

进入左侧 **“实例”**，选中目标，再打开配置或管理操作。首页适合快速选择并启动，实例页适合看清多个环境的状态。

在管理入口可以重命名、更换图标、打开游戏目录和版本目录。图标支持 PNG 或 JPEG，文件不超过 4 MiB；启动器保存自己的副本，原图片保持不变。

建议用“林地生存”“建筑练习”“伙伴联机”一类按用途命名，避免全叫“新实例”。

## 创建完整副本

选择 **“创建副本”**，核对新名称与任务范围后开始。它复制游戏内容、世界、配置和所选版本，安全复用共享依赖，来源保留。

复制前正常退出游戏，避免存档还在变化。任务完成后再启动副本；两边后续的世界进度各自独立，不会自动同步。

## 为一个实例调整配置

使用实例配置修改它自己的 Java、内存和运行选项。全局设置提供默认值，实例覆盖用于特殊需求；恢复继承可重新使用全局值。

配置变更需要按页面确认。一个实例出问题时先查它自己的覆盖项，避免为了修好一套游戏把所有实例的默认配置都改掉。运行环境的准备与更换也在实例相关入口进行，先备份，再查看实际任务。

## 备份和恢复全部游戏内容

**“备份全部游戏内容”**包括这个实例的世界和配置，适合大改动前使用；共享依赖留在数据目录。备份前退出游戏，运行中不能保证一致快照。

恢复时选择正确记录，核对时间。恢复会覆盖备份中包含的文件，同时保留其他文件；启动器会先建立安全备份与回退位置。它不等于把整个实例严格清空到旧时刻。只想恢复一个世界时，使用[世界备份](/docs/play/worlds)。

## 用这套实例创建房间

想用这套实例招待朋友，可在菜单选择 **用此实例创建房间**，随后选择存档并启动。已经运行的游戏也会按实际会话处理；有多个游戏时需明确目标。操作见[联机指南](/docs/play/multiplayer)。

## 导出整合包与完整备份不同

导出整合包用于打包玩法和配置给其他人。当前界面的 Modrinth 包导出**不含世界、Java 和共享游戏依赖**，不能代替存档备份。导出前检查要分发的文件和各内容作者的要求。

## 移除登记与删除文件

先读确认框中的范围：

- 仅移除登记：保留游戏文件、世界、备份和共享依赖。
- 同时删除实例文件：会删除这个实例拥有的游戏内容，包括世界和配置；保留的备份与共享依赖按提示处理。此删除不能撤销。

> [!WARNING]
> 遇到文件占用或中断，先关闭游戏、修正权限后按提示重试。不要手工清空共享依赖目录，其他实例可能仍在使用。
