description: 选择完整复制迁入，或直接链接既有游戏与存档。

## 导入会发生什么

导入菜单提供两种方式：**导入游戏目录**采用迁移复制，得到独立副本；**链接既有实例**直接使用原目录，不复制大型存档。两种方式都不删除来源。

## 直接链接既有实例

1. 在首页或“实例”的导入菜单选择“链接既有实例”。
2. 选择包含 `versions` 的 `.minecraft` 目录，核对自动发现的版本与真实游戏目录。默认全选，也可以只勾选需要的版本。
3. 如果来源没有明确的版本隔离策略，为对应版本选择共享游戏目录或版本独立目录；不要把依赖根误当作存档位置。
4. 点击“链接所选版本”，创建非托管实例。重复链接会复用相同登记，不会再复制或创建重复实例。

RMCL 的个性化启动参数保存在自己的元数据中，不回写 HMCL、PCL 或原版启动器配置；已有存档不转换。移除非托管实例仅解除登记，不删除原游戏文件。

> [!IMPORTANT]
> 链接后多个启动器使用的是同一份游戏数据。游戏内设置、模组和存档的变化会相互可见；不要同时运行同一目录。重要世界仍应备份。

## 复制迁入独立副本

选择“导入游戏目录”时，启动器复制选定游戏内容、所需版本链、共享资源和可读取的 Java，全部复制后才登记实例，不改写来源。下方步骤适用于这种复制方式。

> [!IMPORTANT]
> 完成后是两份独立游戏。以后在旧启动器产生的新进度不会自动出现在 RMCL，反过来也一样。

## 1. 先保存退出

正常退出 Minecraft，让文件停止变化。重要世界另外留一份备份。目标磁盘要有完整副本的空间，不能只看版本文件大小。

## 2. 找到来源

从原启动器使用“打开游戏目录”之类的入口，找到实际游戏位置。桌面快捷方式所在目录不一定是游戏目录。

旧启动器可能把版本、共享资源和 Java 放在不同位置。记录它们，导入界面需要时再补充。如果手里是 .mrpack 或整合包 ZIP，改走[整合包导入](/docs/play/modpacks)。

## 3. 选择目录并核对

进入 **“实例”** 的导入游戏目录入口；首页新建按钮旁的菜单也提供导入选择。

选择来源，根据识别结果补充需要的位置，核对版本、实例名称和目标目录。无法识别时先读提示，保留未知配置与文件，不要通过删文件或改扩展名来凑结果。

## 4. 等待复制完成

任务显示真实字节进度。很多小文件或大型包需要较长时间，可以看当前文件和任务状态。若取消或失败，保留来源，先解决空间、权限或缺文件问题。

来源本身缺少的文件不会因为复制就自动出现。按任务提示补齐来源或继续准备运行环境，不要直接清空共享资源。

## 5. 启动检查后再安排旧副本

1. 找到新实例，核对版本与运行配置。
2. 启动游戏，检查世界、模组和设置。
3. 确认以后主要使用哪份副本，避免世界进度分叉。
4. 验证完成后，再自行安排旧目录。

## 改数据目录能代替导入吗

不能。数据目录修改在重启后生效，不自动搬动旧游戏。使用明确的迁移流程，并保留旧副本到验证结束。
